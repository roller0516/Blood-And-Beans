## 3. 완료한 것 (1~5단계 구현 + QA 정적·부분 회귀)

### 1단계 — 코어 루프 닫기

밤에 캔 것이 낮의 재료가 된다. 이전에는 `IngredientShelf`가 무한 재고라 밤과 낮이 자원으로 이어져 있지 않았다.

- `Day/TeamStock.cs` 신설 — 팀 재고(`NetworkList<int>`, 재료별 개수)
- `Night/ReturnZone` — 밤 종료 시 미귀환 50% 소실 → 잔량을 `TeamStock`에 적립. `PhaseEntered` 구독으로 전환(폴링 제거)
- `Day/IngredientShelf` — 상비 재료(원두·빵 베이스)만 무한, 나머지는 재고에서 차감
- `Rules/Ingredients.IsStaple` — 상비 재료 판정의 유일한 원천

**실측:** 인벤토리에 Milk×3·Berry×2·Bean 주입(무게 5.6) → 귀환 지점 밖에서 전환 → 절반 소실 후 team0 재고 Milk1, team1 재고 0, Bean은 상비라 미적립. 선반 사이클이 team0에서 `Bean·BreadBase·Milk`, team1에서 `Bean·BreadBase`.

### 2단계 — 신뢰 경계

| 결함 | 조치 |
|---|---|
| 밤 루팅 전체가 클라 시간 판정 | `Rules/HoldTimer` 신설. 클라는 눌림·뗌만 보고하고 서버가 잰다. `ItemBox`·`Sink` 적용 |
| 카페 A의 F가 카페 B의 게이지를 멈춤 | 후보 집합을 `Cafe.Gauges`로 좁히고 `StopRpc`에서 발신자 팀 재검증 |
| 낮 설비에 팀 검증 없음 | `Cafe.SameTeamServer()`를 shelf·counter·sink·station RPC에 적용 |
| 대시 중단이 클라 진행도를 건드림 | `PlayerInteract`가 서버측 대상 원천이 되고, 중단은 박스의 `HoldTimer.Halve` |

### 3단계 — 어셈블리와 테스트

| 어셈블리 | 위치 | 성격 |
|---|---|---|
| `BB.Rules` | `Assets/Scripts/Rules/` | `noEngineReferences: true`. 규칙에 UnityEngine이 못 들어온다 |
| `BB.Game` | `Assets/Scripts/` | 나머지 전부 |
| `BB.Tests.EditMode` | `Assets/Tests/EditMode/` | `BB.Rules`, `BB.Game`, `Unity.Netcode.Runtime` 참조 |

`Rules/`: `Ingredients` `MenuDef` `SalePrice` `Rent` `Forecast` `HoldTimer` `LoadBands` `TeamLedger`.
수동 실행이던 셀프체크 2종은 삭제하고 NUnit 테스트로 흡수했다.

**테스트가 잡아낸 실제 결함:** `Forecast`의 "기본 메뉴 20% 상한"(기획서 5.5 규칙 4)이 죽은 코드였다. 아메리카노를 `menus[pick].Count == 0`으로 판정하는데 호출자는 원두가 포함된 전체 레시피를 넘겨서 조건이 한 번도 참이 되지 않았다. "상비 재료만으로 이뤄진 메뉴"로 고쳤다.

### 4단계 — 팀 원천 단일화

- `Core/MatchDirector.cs` 신설 — 팀 슬롯 배열(`cafeSlots`/`fogSlots`)이 팀 id의 정의. `Cafe`·`FogOfWar`에 주입, 좌석 배정, 팀별 `TeamLedger` 보유
- MonoBehaviour다. 슬롯은 씬 데이터라 모든 피어가 같은 답을 로컬 계산한다 — 복제하지 않는다
- `Rules/TeamLedger.cs` 신설 — 팀별 임대료·부채·페널티. 매출은 모른다(기획서 3.3)
- `Player/PlayerCarry.cs` 신설 — `HeldItem`이 여기로 이동

**제거한 static 5종**

| 사라진 것 | 어디로 |
|---|---|
| `Hands` (clientId→HeldItem) | `PlayerCarry` 컴포넌트 |
| `Penalties.ByTeam` | `TeamLedger` (파일째 삭제) |
| `FogOfWar.All` | `MatchDirector.FogOf(team)` |
| `CompletionGauge.Live` | `Cafe.Gauges` |
| `GamePhase.PhaseEntered` static event | 인스턴스 이벤트 |

`Cafe.teamId`·`FogOfWar.teamId`의 `[SerializeField]`도 제거했다.

### Codex QA 및 5단계 — 입력·표현 분리

- 상세 근거와 최초 결함은 [qa-final.md](qa-final.md)에 보존했다. 치명 1건·높음 12건의 정적 구현 결함을 수정했다.
- `BB.Client` 신설: `PlayerInputRouter`, uGUI HUD, 고객·안개·박스 표현을 이동했다.
- `PlayerInteractor` + 실제 구현 5종의 `IInteractable`: 트리거 진입/이탈 후보만 유지하며 프레임당 전역 탐색을 제거했다.
- `.inputactions`의 Move/Interact/Jump(Dash)/Crouch(Dump)를 실제 사용한다. Interact 키는 기획 기준 F다.
- `PlayerMove`는 입력 벡터만 Owner RPC로 받고 서버가 이동한다. Player `NetworkTransform.AuthorityMode`는 Server다.
- 박스 개봉·공개와 안개 셀은 팀 대상 RPC만 사용한다. 상대 카페는 `NetworkHide`, 동적 손님은 팀에만 `NetworkShow`하며 늦게 합류한 같은 팀에도 기존 손님을 다시 공개한다.
- 매 밤 박스 리롤, 예보 주문 소비, 팀별 보유 재료 30%, Night0/15초 보호, 설비 레시피 구분, 무작위 절반 손실, 수동 배낭 쏟기를 반영했다.
- 완료 기준 실측: `BB.Game`의 `Keyboard`·`OnGUI`·`Renderer` 참조 각 0건.
