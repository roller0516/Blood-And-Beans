## 1. 한 문장

**폐허 속의 낙원.** 낮의 카페는 이 세계에서 유일하게 따뜻한 색을 가진 장소이고, 밤은 그 색이 전부 빠진 같은 공간입니다.

이 대비가 아트의 전부입니다. 낮 화면과 밤 화면을 나란히 놓았을 때 **같은 게임으로 안 보이면 성공**입니다.

## 2. 시점 — 쿼터뷰 하나로 통일

이전 안은 낮 사이드뷰 / 밤 탑다운이었습니다. **폐기합니다.** 시점이 둘이면 인물 스프라이트가 두 벌이고, 낮에 익힌 공간 감각이 밤에 통째로 리셋됩니다. 이 게임은 **낮에 꾸민 카페를 밤에 남이 털러 오는** 게임이라, 두 페이즈가 같은 공간으로 읽히지 않으면 핵심이 죽습니다.

쿼터뷰가 두 요구를 동시에 만족합니다.

| 요구 | 쿼터뷰의 답 |
|---|---|
| 낮: 손님 얼굴·줄·주문이 읽혀야 함 | 인물이 정면 상체를 보이면서 서 있음. 표정 영역(6×6) 확보 |
| 밤: 시야·소음 반경, 좀비 거리감 | 지면이 평면이라 반경을 **타일 다이아몬드**로 정확히 그림 |
| 카페 배치가 자산이어야 함 | 가구가 부피를 가짐. "내가 꾸민 공간"이 화면에 보임 |

**비용:** 인물 4방향이 필요합니다. 좌우 대칭으로 2벌만 그리고(남동/남서 → 미러로 북동/북서) 총 2벌로 묶습니다. 사이드+탑다운 2벌과 같은 비용에 시점은 하나입니다.

## 3. 해상도와 픽셀 그리드

| 항목 | 값 | 이유 |
|---|---|---|
| 논리 해상도 | **320 × 180** | 16:9. 2×/3×/4×/6× 정수 확대로 4K까지 떨어집니다 |
| 확대 방식 | 최근접 이웃 (`image-rendering: pixelated`) | 픽셀 경계가 뭉개지면 도트가 아닙니다 |
| 타일 | **32 × 16 다이아몬드 (2:1)** | 아이소 표준. 경사 계단이 `2px 가로 : 1px 세로`로 딱 떨어져 앨리어싱이 안 생깁니다 |
| 높이 단위 | **8px** | 1 유닛 = 8px. 카운터 14 ≈ 2유닛, 벽 32 = 4유닛 |
| 화면 수용량 | 바닥 8 × 6 타일 + 벽 2면 | 320×180에 정확히 들어갑니다 |
| 서브픽셀 | **금지** | 스크린 좌표는 그릴 때 `\|0`. 카메라도 정수 픽셀로만 |

### 좌표 변환 (이대로 구현합니다)

```
sx = OX + (tx - ty) * 16
sy = OY + (tx + ty) * 8 - z
```

`z`는 타일 단위가 아니라 **픽셀**입니다. 높이를 픽셀로 두면 14px 카운터, 10px 테이블처럼 유닛에 안 맞는 가구를 억지로 반올림할 일이 없습니다.

### 깊이 정렬

**페인터 알고리즘, 키는 `tx + ty`.** 같은 값이면 `z` 오름차순.
바닥 → 벽 → 나머지 전부(가구·인물 한 배열에 섞어서 정렬) 순서로 그립니다. 가구와 인물을 따로 그리면 손님이 테이블을 뚫습니다.

### 색 사용 규칙 (이게 핵심입니다)

1. **배경은 무채색에 가깝게.** 재·중립 5색과 night-0/1만 씁니다.
2. **채도는 정보다.** amber-3, night-3, blood-2 — 이 세 색은 **플레이어가 반응해야 하는 것**에만 붙습니다. 장식으로 쓰면 화면이 거짓말을 합니다.
3. **낮에는 night-3을, 밤에는 amber-3을 거의 쓰지 않습니다.** 예외는 내 카페(HOME) 표식뿐 — 밤에 유일하게 남은 난색이 집이라는 뜻이니까요.
4. **한 면 = 한 색.** 쿼터뷰에서 광원은 언제나 위. 윗면이 가장 밝고, 좌측면 중간, 우측면 가장 어둡습니다. 이 3단 규칙을 어기면 부피가 무너집니다.
5. 한 스프라이트에 **4색 이하**.

## 5. 인물 스프라이트

| 항목 | 값 |
|---|---|
| 셀 크기 | **12 × 20** (여백 포함) |
| 실제 점유 | 머리 6 × 6, 몸통 8 × 8, 다리 6 × 6 |
| 색 수 | 4색 이하 (머리 / 몸통 / 그림자 / 발) |
| 정렬 | **셀 하단 중앙 = 타일 중심**. 발이 다이아몬드 중앙에 놓입니다 |
| 방향 | 남동 · 남서 2벌 (북동·북서는 각각 미러 + 머리 뒤통수색) |

타일이 32×16인데 인물이 12×20인 건 의도입니다. 인물이 타일보다 세로로 길어야 서 있는 것으로 읽힙니다.

### 애니메이션 — 프레임을 늘리지 않습니다

| 동작 | 프레임 | 비고 |
|---|---|---|
| 대기 | 1 | 2초 주기 1픽셀 호흡(코드로 처리, 프레임 불필요) |
| 걷기 | **2** | 발 좌/우. 초당 6프레임 |
| 달리기 | 2 | 걷기 프레임 그대로, 재생 2배 + 몸통 1픽셀 전방 |
| 제조(바리스타) | 3 | 잔 들기 → 붓기 → 내밀기 |
| 피격 | 1 | 전체 blood-1 실루엣. 0.1초 |
| 사망 | 3 | 무릎 → 엎어짐 → 바닥 얼룩 |

**필요하다고 판명되기 전까지 프레임을 추가하지 않습니다.**

### 변형
- 손님: 머리색 3종 × 몸통색 4종 = 12조합을 **색 교체로** 생성. 스프라이트는 1개.
- 좀비: 같은 스프라이트에 night-2 / night-3 팔레트 교체 + 걷기 재생 0.6배.
- 플레이어: 몸통 wood-0, 머리 bone-2 고정 — 밤 화면에서 유일하게 밝은 인물이어야 합니다.

## 6. 배경과 소품

- **바닥은 32×16 다이아 두 색 체커.** 규칙적 패턴이 쿼터뷰의 거리 감각을 만듭니다.
- 가구는 **박스 프리미티브**로 조립: 윗면 다이아 + 좌측면 + 우측면. 높이만 다릅니다.
  - 카운터 14px / 테이블 10px / 선반 26px / 로스터 24px / 벽 32px
- 반 타일(16×8) 소품: 테이블, 상자, 머신. 풀 타일 소품: 카운터, 로스터, 선반, 벽.
- **디테일은 소품에만.** 바닥과 벽은 비워 둡니다. 320×180에서 배경이 시끄러우면 인물이 사라집니다.
- 창밖은 항상 잿빛(`bone-0`을 어둡게 쓴 면). 카페 안이 따뜻한 건 밖이 그렇지 않기 때문입니다.
- **조명은 그라디언트가 아니라 타일에 굽습니다.** 램프 반경 1타일 내 바닥은 amber-0 / soot-4 체커, 3타일까지 soot-4 / soot-3, 그 밖은 soot-3 / soot-2. 부드러운 빛 대신 **색 계단**을 씁니다.

## 7. 밤 연출

| 요소 | 규격 |
|---|---|
| 바닥 | night-1 / night-0 체커. 낮과 **완전히 같은 타일 배치** |
| 시야 | 플레이어 중심 반경 10px 완전 밝음 → 88px에서 `rgba(4,8,7,.93)`. 원형 그라디언트 |
| 소음 반경 | 걷기 22px(night-3, α.22) / 달리기 55px(blood-2, α.5) **1px 외곽선만** |
| 좀비 구역 | 반경 58px, night-1 채움 + night-2 점선(3px 대시 / 4px 간격) |
| 남의 카페 | **발견 전에는 그리지 않습니다.** 발견 후 blood-2 16×8 다이아 표식 + 이름표 |
| 내 카페 | amber-3 16×8 다이아. 밤 화면의 유일한 난색 |

시야 밖을 완전한 검정으로 만들지 않습니다(`night-0`). 완전 검정은 화면이 꺼진 것처럼 보입니다.

## 8. 텍스트와 UI — 월드에 한글을 그리지 않습니다

320×180에서 한글 최소 가독 높이는 11~12px, 화면 높이의 1/15입니다.

| 레이어 | 내용 | 방식 |
|---|---|---|
| 월드 | 캐릭터, 타일, 이펙트, **아이콘과 색** | 320×180 캔버스 |
| UI | 수치, 이름, 로그, 결산, 메뉴판 | 캔버스 위 별도 레이어 (실제 픽셀 해상도) |

월드의 정보는 **글자 대신 아이콘과 색**. 손님 선호 태그는 한글이 아니라 6×6 아이콘(각설탕/커피콩/레몬/견과/봉인 캔)으로 표시하고, 인물 머리 위 8×8 말풍선에 얹습니다.

- UI 서체: 픽셀 계열 한글 폰트(갈무리, 둥근모꼴 계열). **상업 이용 라이선스를 확인**하고 여기에 기록합니다.
- 라틴/숫자 라벨(DAY, SALES, RANK)은 픽셀 서체(Silkscreen 등)로 분리해 대비를 만듭니다.
- 숫자는 고정폭(`tabular-nums`). 매출이 흔들리면 싸구려로 보입니다.

## 9. 이펙트

전부 도트로 직접 찍습니다. 파티클 시스템의 부드러운 그라디언트를 쓰지 않습니다.

| 이펙트 | 방식 |
|---|---|
| 판매 성공 | `+15G` 텍스트가 14px/초 상승, 1.1초 알파 감소. 적중 amber-3 / 불일치 blood-2 |
| 김(수증기) | 2×2 픽셀 3개가 위로 흔들리며 소멸 |
| 피격 | 화면 전체 1프레임 blood-1 오버레이 + 인물 실루엣 플래시 |
| 상자 개봉 | 뚜껑 다이아가 1픽셀 위로 → 8프레임 후 soot-4로 변색 |
| 습격 진행 | 하단 80×5 게이지. 아이콘 없이 바 하나 |

**화면 흔들림은 피격과 사망에만.** 남발하면 픽셀 정렬이 무너져 보입니다.

## 10. 하지 않을 것

- 안티앨리어싱, 소프트 그림자, 블러, 블룸 — 픽셀 경계를 흐리는 모든 것 (예외: 밤 시야 원형 그라디언트 1개)
- 도트 위에 얹는 고해상도 UI 아이콘 (해상도가 섞이면 둘 다 싸 보입니다)
- **스프라이트 회전.** 쿼터뷰에서 회전은 방향별로 그려서 해결합니다
- 2:1이 아닌 아이소 비율. 자유 각도는 계단이 지저분해집니다
- 팔레트 밖의 색. "이번만" 쓴 색이 다음 화면에서 기준이 됩니다
- 24색을 넘기기 전에 그림을 늘리기

## 11. 작업 순서

1. **팔레트 스와치 파일**(24색 `.gpl`/`.hex`) — 이게 없으면 아무것도 시작 안 합니다
2. **타일 3종**: 바닥 A/B, 벽 1종. 32×16 그리드 검증용
3. 박스 프리미티브(윗면/좌/우) 조립 규칙 코드화 — 가구는 여기서 파생
4. 인물 베이스 1종(남동 대기 1 + 걷기 2) → 색 교체로 손님·좀비 파생, 미러로 남서
5. 낮 카페 1화면 완성 — 바닥, 벽 2면, 창, 카운터, 소품 4종
6. 같은 화면의 밤 버전 — 팔레트 교체 + 시야 + 표식 2종(HOME/RIVAL)
7. 맛 아이콘 5종 (6×6) · 이펙트 5종
8. 여기까지가 MVP. 시설·방어 설비 아트는 그 다음입니다

## 12. 미결

- **인물 2벌(남동/남서)로 4방향이 실제로 읽히는지.** 4번 단계 끝나고 판단합니다. 안 되면 4벌로 늘립니다.
- 한글 픽셀 폰트 라이선스 확정.
- 24색이 부족한 지점 — 5번 단계 이후 실측. 유력 후보는 **금속/유리 중간톤**과 **좀비 피격색**.
