## 0. v2.0에서 바뀐 것

v1.x는 320×180 / 32×16 타일 / 인물 12×20 / 24색이었습니다. **폐기합니다.**

12×20 인물에는 표정이 안 들어가고, 24색으로는 재질(나무·금속·유리·천)이 구분되지 않습니다. 기획서 §6.1이 오버쿡식 제조로, §7.2가 타르코프식 루팅으로 확정되면서 화면이 **읽어야 할 정보**가 늘었습니다 — 스테이션 상태, 컨테이너 3상태 아웃라인, 검색 프로그레스, 손님 대기 게이지가 전부 동시에 떠 있어야 합니다. 저해상도로는 이 정보량이 안 들어갑니다.

| | v1.x | **v2.0** |
|---|---|---|
| 논리 해상도 | 320 × 180 | **640 × 360** |
| 타일 | 32 × 16 | **64 × 32** |
| 인물 셀 | 12 × 20 | **40 × 64** |
| 팔레트 | 24색 (평면) | **40색 (10 램프)** |
| 조명 | 타일에 구움 | **URP Light2D 실시간** |
| 엔진 | (미정) | **Unity 6 · URP 2D Renderer** |

도트는 유지합니다. 해상도만 올립니다 — 벡터도 회화풍도 아닙니다.

## 1. 한 문장

**폐허 속의 낙원.** 낮의 카페는 이 세계에서 유일하게 따뜻한 색을 가진 장소이고, 밤은 그 색이 전부 빠진 같은 공간입니다.

낮 화면과 밤 화면을 나란히 놓았을 때 **같은 게임으로 안 보이면 성공**입니다.

## 2. 그리드 — 64 × 32, 2:1

| 항목 | 값 | 이유 |
|---|---|---|
| 논리 해상도 | **640 × 360** | 2× = 720p, 3× = 1080p, 4× = 1440p, 6× = 4K. 전부 정수배 |
| 타일 | **64 × 32** | 아이소 2:1. 경사 계단이 `가로 2px : 세로 1px`로 떨어집니다 |
| 높이 단위 | **16px** | 카운터 28(≈2), 벽 64(=4), 테이블 20 |
| PPU | **32** | 타일 = 정확히 2 × 1 Unity 유닛. 좌표 계산에 소수점이 안 생깁니다 |
| 화면 수용량 | 바닥 **10 × 8** 타일 + 벽 2면 | 640×360에 들어갑니다 |
| 서브픽셀 | **금지** | 스크린 좌표는 그릴 때 정수. 카메라도 정수 픽셀로만 |

### 좌표 변환

```
sx = OX + (tx - ty) * 32
sy = OY + (tx + ty) * 16 - z
```

`z`는 타일 단위가 아니라 **픽셀**입니다. 28px 카운터, 20px 테이블처럼 유닛에 안 맞는 가구를 억지로 반올림할 일이 없습니다.

### 깊이 정렬

Unity에서는 **Transparency Sort Mode = Custom Axis (0, 1, 0)** 으로 두고 월드 Y로 정렬합니다. `sortingOrder`를 직접 계산하지 않습니다 — 오브젝트가 움직이면 매 프레임 갱신해야 하고, 그게 아이소 정렬 버그의 주범입니다.

- 스프라이트 피벗을 **발밑(Bottom-Center)** 에 두면 Y 정렬이 곧 `tx + ty` 정렬이 됩니다.
- 여러 타일을 덮는 큰 가구(카운터 3칸)는 **타일 단위로 쪼갭니다.** 한 덩어리로 두면 반드시 뚫립니다.
- 같은 Y에서의 순서만 `Sorting Order` 보조 사용 (바닥 −100 / 그림자 −50 / 본체 0 / 오버레이 +50).

## 3. 팔레트 — 46색 / 11 램프

**이 팔레트는 컨셉 아트에서 실측했습니다.** v2.0의 40색은 v1.x의 24색을 눈대중으로 늘린 것이었고, Codex `imagegen`이 만든 컨셉 2장을 실제로 측정하니 두 군데가 틀렸습니다.

### 실측으로 드러난 것

**(1) 밤은 파랑이다. 초록이 아니다.**
v2.0은 밤 환경과 좀비를 `night` 램프 하나로 묶었습니다. 컨셉 밤 화면의 지배색을 재보니 H≈213의 **파랑**(`#0D1826` 13% · `#202D40` 6.6%)이었고, 초록은 좀비에만 있었습니다.
같은 램프로 묶으면 **"좀비가 있는 곳"과 "그냥 어두운 곳"이 구분되지 않습니다.** 그래서 `dusk`(밤 환경, 파랑)와 `rot`(좀비 피부, 초록)을 분리했습니다.

**(2) 낮은 더 붉고 어둡다.**
v2.0의 amber는 노랑에 가까웠습니다. 실측치는 H 11~29의 **적갈색 계열**(`#78381A` · `#A95A2A` · `#562713`)이 지분 상위였고, 노랑(`#FDCD6F`)은 조명 하이라이트로만 소량 쓰였습니다. 카페가 따뜻해 보이는 건 화면이 노래서가 아니라 **어두운 적갈색 위에 밝은 점광이 몇 개 있기 때문**입니다.

### 검증

두 팔레트를 컨셉 아트에 대고 픽셀당 최근접 색 거리를 재면(낮을수록 재현이 정확):

| | 낮 카페 | 밤 습격 |
|---|---|---|
| **실측 46색** | **14.54** | **7.30** |
| v2.0 계열 40색 | 19.10 | 11.61 |

### 램프

램프는 `이름-0`(최암부) → `이름-n`(최명부). 팔레트 파일은 `Art/make_palette.py`가 생성합니다 (`Art/out/palette.png` · `.gpl` · `.hex` · `.json`).

| 램프 | 색 | 용도 |
|---|---|---|
| **soot** (5) | `#06060B` `#10101A` `#1C1C26` `#2B2B33` `#3C3F40` | 중립 암부. 낮/밤 공통 배경, 패널 |
| **amber** (6) | `#331109` `#562713` `#78381A` `#A95A2A` `#E09A45` `#FDCD6F` | 낮의 온기. `amber-4`가 주조색, `amber-5`는 조명 하이라이트 |
| **wood** (4) | `#2A2214` `#453E23` `#6B5733` `#8D7A58` | 카운터, 선반, 테이블, 상자 |
| **bone** (4) | `#4A443B` `#6E6656` `#A2957E` `#E8DCC8` | 텍스트, 종이, 플레이어 머리. `bone-3`이 화면에서 가장 밝은 색 |
| **dusk** (6) | `#050710` `#08101A` `#0D1826` `#121D29` `#202D40` `#3A4A60` | **밤 환경.** 지면, 건물, 벽 |
| **rot** (4) | `#24301C` `#4A5A2A` `#7A9A4A` `#A8C46A` | **좀비 피부.** 밤 환경과 분리 |
| **toxic** (2) | `#2A6B58` `#5FD3A6` | 좀비 눈, 소음 반경, 안전 신호 |
| **blood** (4) | `#2A0C0A` `#5E1A12` `#9B2E28` `#D9463C` | 남의 카페, 습격, 피격 |
| **skin** (4) | `#4E3828` `#7A5C42` `#C9B79A` `#E5D4B8` | 살결 |
| **steel** (4) | `#1C2024` `#343C44` `#5E6A74` `#9AA8B2` | 에스프레소 머신, 그라인더, 자물쇠 |
| **glass** (3) | `#26343A` `#4A6A72` `#8FBFC4` | 창, 진열장, 유리병 |

### 색 사용 규칙

1. **배경은 무채색에 가깝게.** `soot` 램프와 `dusk-0/1`만.
2. **채도는 정보다.** `amber-5` · `toxic-1` · `blood-3` — 이 셋은 **플레이어가 반응해야 하는 것**에만 붙습니다. 장식으로 쓰면 화면이 거짓말을 합니다.
3. **낮에는 toxic을, 밤에는 amber를 거의 쓰지 않습니다.** 예외는 내 카페(HOME) 표식뿐 — 밤에 유일하게 남은 난색이 집이라는 뜻이니까요. 컨셉 밤 화면의 오른쪽 아래 앰버 표식이 그 예입니다.
4. **밤 환경(dusk)과 좀비(rot)를 섞지 않습니다.** 섞이면 위험 판독이 무너집니다.
5. **광원은 언제나 위.** 윗면 = 램프 상위단, 좌측면 = 중간, 우측면 = 하위단.
6. **램프를 건너뛰지 않습니다.** 4 → 2 로 점프하면 면이 찢어져 보입니다. 4 → 3 → 2.
7. 한 스프라이트에 **램프 3개 이하** (몸통 / 피부 / 소품).

## 4. HD 도트를 HD답게 만드는 것

해상도만 올리고 v1.x처럼 그리면 **그냥 큰 도트**가 됩니다. 아래 네 가지가 실제 차이를 만듭니다.

### (1) 디더 — 램프 사이를 잇는다
40색으로 부드러운 면을 만들려면 두 램프 단계 사이를 **체커 디더**로 섞습니다.
- 디더는 **면의 경계에만**, 폭 2~4px. 면 전체를 디더로 채우면 지저분해집니다.
- 패턴은 `50%` 체커 한 종류만 씁니다. 25%/75% 디더는 HD에서 노이즈로 보입니다.

### (2) 셀렉티브 아웃라인
- 캐릭터는 **바깥 실루엣에만** 1px 아웃라인. 내부 선은 색 경계로 처리합니다.
- 아웃라인 색은 검정이 아니라 **해당 램프의 0단**. 검정 아웃라인은 스티커처럼 보입니다.
- 밝은 배경에 닿는 쪽은 아웃라인을 어둡게, 어두운 배경에 닿는 쪽은 **아웃라인을 생략**합니다.

### (3) 재질별 표현
| 재질 | 처리 |
|---|---|
| 목재 | 결 1px 라인 3~4줄, 램프 1단 차이로만 |
| 금속 | 상단 1~2px `steel-3` 하이라이트 + 하단 `steel-0` 반사광 |
| 유리 | `glass-1` 채우고 **대각선 2px 하이라이트 1줄** |
| 천 | 주름은 그림자만, 하이라이트 금지 |
| 세라믹(잔) | 윗면 타원 `bone-3`, 몸통 2단 램프 |

### (4) 서브픽셀 없는 애니메이션
프레임을 늘리는 대신 **1px 단위의 정확한 움직임**으로 무게를 만듭니다.
- 걷기 2프레임이라도 몸통이 **1px 상하**로 움직이면 발이 땅을 짚는 느낌이 납니다.
- 대기는 2초 주기 1px 호흡 — 코드로 처리, 프레임 불필요.

## 5. 인물 — 40 × 64

| 항목 | 값 |
|---|---|
| 셀 | **40 × 64** |
| 실제 점유 | 머리 20 × 20, 몸통 24 × 22, 다리 18 × 20 |
| 피벗 | **Bottom-Center** — 발이 타일 다이아 중심에 놓입니다 |
| 색 | 램프 3개 이하 + 아웃라인 |
| 방향 | **남동 · 남서 2벌**, 북동·북서는 미러 + 뒤통수(얼굴 → 머리색) |

40×64면 **눈·입·옷 주름·손에 든 잔**이 들어갑니다. 그게 12×20에서 올라온 이유의 전부입니다.

### 애니메이션

| 동작 | 프레임 | 비고 |
|---|---|---|
| 대기 | 1 | 2초 주기 1px 호흡 (코드) |
| 걷기 | **4** | HD에서 2프레임은 뚝뚝 끊깁니다. 접지 2 + 중간 2 |
| 달리기 | 4 | 걷기 유지, 재생 1.8배 + 상체 2px 전방 기울임 |
| **들기/놓기** | 2 | 기획서 §6.1 오버쿡 조작. 잔·원두를 든 상태는 **몸통 프레임 + 소품 레이어** 합성 |
| **운반 중 걷기** | 4 | 걷기 프레임 재사용 + 팔 위치만 다른 오버레이 |
| 제조(스테이션 앞) | 3 | 손 올림 → 작동 → 대기 |
| **수색(루팅)** | 2 | 기획서 §7.2. 쭈그려 앉아 서랍 뒤짐. 루프 |
| 피격 | 1 | 전체 `blood-2` 실루엣 + 아웃라인만 `blood-3`. 0.1초 |
| 사망 | 4 | 무릎 → 손짚음 → 엎어짐 → 바닥 얼룩 |

**필요하다고 판명되기 전까지 프레임을 추가하지 않습니다.**

### 변형
- 손님: **머리 4종 × 몸통 팔레트 4종 = 16조합**을 색 교체로 생성. 스프라이트는 1벌.
- 좀비: 같은 베이스에 `night` + `rot` 램프 교체 + 자세 오프셋(고개 15° 숙임) + 걷기 재생 0.6배.
- 플레이어: 몸통 `wood-1`, 머리 `bone-3` 고정 — 밤 화면에서 유일하게 밝은 인물이어야 합니다.

## 6. 배경과 소품

- **바닥은 64×32 다이아 두 색 체커.** 규칙적 패턴이 쿼터뷰의 거리 감각을 만듭니다.
- 가구는 **박스 프리미티브**(윗면 다이아 + 좌측면 + 우측면)로 조립하고, 그 위에 재질 디테일을 올립니다.

| 소품 | 크기 | 높이 |
|---|---|---|
| 벽 | 64×32 | 64 |
| 카운터 | 64×32 | 28 |
| 그라인더 · 에스프레소 머신 · 서빙대 | 32×16 | 24~36 |
| 원두 선반 | 64×32 | 52 |
| 테이블 | 32×16 | 20 |
| 서랍·캐비닛 | 32×16 | 24 |
| 컨테이너 | 64×32 | 32 |
| 랜덤 박스 | 32×16 | 28 |

- **디테일은 소품에만.** 바닥과 벽은 비웁니다. 배경이 시끄러우면 인물이 사라집니다.
- 창밖은 항상 잿빛(`bone-1` / `soot-3`). 카페 안이 따뜻한 건 밖이 그렇지 않기 때문입니다.

## 7. 조명 — Unity URP 2D Light

v1.x는 조명을 타일 색에 구웠습니다. v2.0은 **Light2D로 실시간 처리**합니다. 카페를 키우면 조명도 늘어야 하는데(기획서 §6.4), 구운 색으로는 그게 불가능합니다.

| 요소 | 설정 |
|---|---|
| Global Light | 낮 `#FFF0D8` intensity 0.85 / 밤 `#16242A` intensity 0.22 |
| 카페 조명 | Point Light2D, `amber-4`, radius 5 유닛, Falloff 0.6 |
| 손전등(밤) | Spot Light2D, `bone-3`, inner 30° / outer 55°, radius 6 유닛 |
| 스테이션 작동 중 | Point Light2D, radius 1.5, 작동 중에만 켜짐 — **상태 표시를 조명이 대신합니다** |
| 좀비 구역 | Global 위에 `night-2` Freeform Light2D, intensity 0.15 |

**규칙:** Light2D는 쓰되 **Bloom·Blur 포스트프로세싱은 금지**합니다. 픽셀 경계가 뭉개지면 HD 도트가 아니라 그냥 흐린 그림이 됩니다. 유일한 예외는 밤 시야 바깥의 **하드 컷 비네트**(그라디언트 아님, 알파 계단 3단).

노멀맵은 쓰지 않습니다. 40×64 스프라이트에 노멀맵을 그리는 비용이 얻는 것보다 큽니다.

## 8. 정보 레이어 — 월드에 한글을 그리지 않습니다

640×360이라도 한글 최소 가독 높이는 12px입니다. 월드에 문장을 넣지 않습니다.

| 레이어 | 내용 | 방식 |
|---|---|---|
| 월드 | 캐릭터, 타일, 이펙트, **아이콘과 색** | 640×360 픽셀 퍼펙트 |
| UI | 수치, 이름, 로그, 결산, 메뉴판 | Canvas (Screen Space) — 실제 해상도 |

### 월드 아이콘 (기획서 §6.2 / §7.2)

| 아이콘 | 크기 | 용도 |
|---|---|---|
| 맛 태그 5종 (각설탕/커피콩/레몬/견과/봉인 캔) | **24 × 24** | 손님 머리 위 말풍선 |
| 스테이션 상태 (대기/진행/완료/탄 것) | 20 × 20 | 스테이션 위 |
| 컨테이너 상태 (미개봉/수색중/빈 것) | — | **아웃라인 색**으로만. 아이콘 없음 |

### 컨테이너 아웃라인 — 기획서 §7.2(1)

| 상태 | 색 | 두께 |
|---|---|---|
| 미개봉 | `bone-3` | 2px |
| 수색 중 | `amber-4` | 2px + 1px/프레임 점멸 |
| 이미 턴 것 | `bone-1` | 1px |

**아웃라인은 손전등 반경 안에서만 켜집니다.** 밤 화면은 어둡고, 아웃라인이 사실상 유일한 탐색 단서입니다.

### 서체
- 한글: 픽셀 계열(갈무리·둥근모꼴 계열). **상업 이용 라이선스를 확인하고 여기에 기록합니다.** ← 미결
- 라틴/숫자(DAY, SALES, RANK): 픽셀 서체(Silkscreen 등)로 분리해 대비를 만듭니다.
- 숫자는 고정폭(`tabular-nums`). 매출이 흔들리면 싸구려로 보입니다.

## 9. 이펙트

전부 도트로 직접 찍습니다. 파티클 시스템의 부드러운 그라디언트를 쓰지 않습니다.

| 이펙트 | 방식 |
|---|---|
| 판매 성공 | `+15G` 4px 상승/0.1초, 1.1초 알파 감소. 적중 `amber-4` / 불일치 `blood-3` |
| 김(수증기) | 4×4 픽셀 3개가 흔들리며 상승, 램프 2→1→0으로 식으며 소멸 |
| 과분쇄·탄 것 | 스테이션 위 `blood-3` 연기 + 조명이 `blood-2`로 전환 |
| 검색 프로그레스 | 컨테이너 위 32×4 바. `amber-4` 채움, 슬롯 하나 열릴 때 1프레임 `bone-3` 플래시 |
| 소음 반경 | 걷기 44px(`night-3` α.22) / 달리기 110px(`blood-3` α.5) **1px 도트 외곽선** |
| 피격 | 화면 전체 1프레임 `blood-2` 오버레이 + 인물 실루엣 플래시 |
| 습격 진행 | 하단 160×8 게이지. 아이콘 없이 바 하나 |

**화면 흔들림은 피격과 사망에만.** 남발하면 픽셀 정렬이 무너져 보입니다.

## 10. Unity 임포트 규격 (에셋 넘기기 전 확인)

| 설정 | 값 | 안 지키면 |
|---|---|---|
| Filter Mode | **Point (no filter)** | 도트가 뭉개집니다 |
| Compression | **None** | 색이 밀립니다. 40색 팔레트가 깨집니다 |
| Pixels Per Unit | **32** | 타일이 유닛 격자에 안 맞습니다 |
| Pivot | 인물·소품 **Bottom-Center** / 타일 **Center** | Y 정렬이 틀어집니다 |
| Mesh Type | **Full Rect** | 알파 트리밍으로 피벗이 밀립니다 |
| Sprite Sort Point | **Pivot** | 큰 스프라이트가 뚫립니다 |
| Generate Physics Shape | **Off** | 쓰지도 않을 콜라이더가 임포트를 늘립니다 |
| Max Size | 원본 이상 | 자동 축소되면 도트가 죽습니다 |
| Sprite Atlas | 페이즈별로 분리 (`Atlas_Cafe`, `Atlas_Zone`, `Atlas_Chars`) | 밤에 낮 텍스처가 통째로 올라옵니다 |

- 카메라: **Orthographic**, `size = 360 / 2 / 32 = 5.625`
- **Pixel Perfect Camera** 컴포넌트: Ref Resolution `640 × 360`, PPU `32`, **Upscale Render Texture ON**, Crop Frame X+Y
- Transparency Sort Mode: **Custom Axis (0, 1, 0)**

## 11. 하지 않을 것

- 안티앨리어싱, 소프트 그림자, **블룸, 블러** — 픽셀 경계를 흐리는 모든 것
- 도트 위에 얹는 벡터/고해상도 UI 아이콘 (해상도가 섞이면 둘 다 싸 보입니다)
- **스프라이트 회전.** 쿼터뷰에서 회전은 방향별로 그려서 해결합니다
- 2:1이 아닌 아이소 비율 — 자유 각도는 계단이 지저분해집니다
- 램프 밖의 색. "이번만" 쓴 색이 다음 화면에서 기준이 됩니다
- **노멀맵.** 40×64 스프라이트에 그릴 비용이 얻는 것보다 큽니다
- 46색을 넘기기 전에 그림을 늘리기

## 12. 작업 순서

1. **팔레트 파일**(40색 `.gpl` / `.hex` / `.png` 램프 스트립) — 이게 없으면 아무것도 시작 안 합니다
2. **타일 세트**: 카페 바닥 A/B, 좀비 구역 바닥 A/B, 거리, 벽 1종 — 64×32 그리드 검증
3. **박스 프리미티브 + 재질 규칙 코드화** — 가구는 전부 여기서 파생
4. **인물 베이스 1종**(남동: 대기 1 + 걷기 4 + 운반 4 + 수색 2) → 색 교체로 손님·좀비, 미러로 남서
5. **낮 카페 1화면**: 바닥, 벽 2면, 창, 카운터, 스테이션 3종(그라인더·머신·서빙대), 선반, 테이블
6. **밤 1화면**: 같은 지오메트리의 팔레트 교체 + 손전등 + 컨테이너 3상태 아웃라인 + 표식 2종(HOME/RIVAL)
7. 맛 아이콘 5종(24×24) · 스테이션 상태 4종 · 이펙트 6종
8. **여기까지가 MVP.** 시설·방어 설비 아트는 그 다음입니다

## 13. 미결

- **인물 2벌(남동/남서)로 4방향이 읽히는지.** 4번 단계 끝나고 판단합니다. 안 되면 4벌로 늘립니다.
- **한글 픽셀 폰트 상업 라이선스 확정.** (v1.x부터 이월)
- **걷기 4프레임이 실제로 필요한지.** HD에서 2프레임이 끊긴다는 건 가정입니다 — 5번 단계에서 2프레임 버전과 나란히 놓고 판단합니다.
- **Light2D 실시간 조명의 성능 비용.** 카페 조명 + 스테이션 조명 + 손전등이 동시에 켜지는 최대 개수를 5번 단계에서 실측합니다.
- 46색이 부족해지는 지점 — 6번 단계 이후 실측. 유력 후보는 **불빛에 물든 중간톤**.
- **컨셉 아트와 게임 내 실물의 밀도 차이.** `imagegen` 컨셉은 손으로 찍은 것과 같은 밀도지만, 절차적 생성기(`Art/bnb_art.py`)로 뽑은 결과는 평면적입니다. 실제 에셋은 imagegen 시트를 받아 팔레트 양자화·그리드 정렬해서 쓰고, 생성기는 배치 검증용으로만 씁니다.
