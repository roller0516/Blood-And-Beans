# BLOOD & BEAN — 게임 기획서

> 핵전쟁 이후, 살아남은 사람들에게 커피를 파는 10일. 낮에는 카페를 운영하고, 밤에는 좀비 구역에서 레시피를 훔쳐온다.
> 도트(2D 픽셀) 그래픽 / 온라인 멀티플레이(2~4인) / **1판 10일 ≈ 63분**
>
> **v2.0** · 2026-08-20 · 이전 버전: [v1.1](Blood&Bean_기획서_v1.1.md)
> 엔진: **Unity** · 넷코드: Netcode for GameObjects

---

## 1. 한 줄 정의

**낮에 번 돈으로 카페를 키우고, 밤에 목숨을 걸어 남의 레시피와 재료를 빼앗는 PvPvE 경영 + 탈출(Extraction) 게임.**

승패 조건은 단 하나 — **10일차 종료 시점에 누적 커피 판매 골드가 가장 높은 사람이 승리한다.**

## 2. 핵심 재미 (Core Loop)

```
[낮] 카페 운영 → 골드 획득 → 시설/레시피 등록
        ↓ (결산)
[밤] 좀비 구역 파밍 / 남의 카페 습격 → 재료·레시피·카드 획득 → 귀환
        ↓
[다음 날] 확보한 레시피로 더 비싼 커피 판매
```

플레이어는 매 밤 **"안전하게 파밍할 것인가, 남의 카페를 털 것인가"** 를 고른다.
파밍은 기대값이 낮고 안정적, 습격은 기대값이 높고 실패 시 하루를 통째로 잃는다.
이 선택은 **9번** 주어진다. 한 번의 판단이 전체의 1/9이라 매 밤이 무겁다.

## 3. 승리 조건과 결산

- 판정 지표: **누적 판매 골드**. 보유 골드가 아니라 *판매로 번 총액*이다. (시설 투자를 해도 손해가 아니게 하기 위함)
- 매일 밤이 끝나면 **일일 결산 화면**을 띄운다. 전원 공개.
  - 오늘 판매 수 / 판매 골드 / 누적 골드 / 순위
  - 단, **레시피 보유 목록과 카페 위치는 비공개.**
- 순위만 공개하는 이유: 누가 잘나가는지는 알지만 *왜* 잘나가는지는 모르게 해서, 밤에 정찰할 이유를 만든다.

## 4. 하루의 구조

| 페이즈 | 길이(기본값) | 내용 |
|---|---|---|
| 낮 (운영) | **3분** | 손님 응대, 제조·판매, 시설 구매, 레시피 등록·조합, 방어 설치 |
| 황혼 (준비) | **20초** | 장비 정비, **행상 거래**, 출격 여부 결정 |
| 밤 (침투) | **3분** | 좀비 구역 파밍 / 타 플레이어 카페 습격 |
| 결산 | **15초** | 순위 공개, 다음 날로 |

### 총 플레이 시간 (반드시 여기 안에 들어와야 한다)

| | 계산 | 합계 |
|---|---|---|
| 1~9일차 | `(180+20+180+15)초 × 9` | 59분 15초 |
| 10일차 | 낮 3분 + 최종 결산 40초 | 3분 40초 |
| **한 판** | | **약 63분** |

- **10일차에는 밤이 없다.** 낮 판매가 끝나면 바로 최종 결산이다.
  - 마지막 밤에 턴 레시피는 팔 날이 없어 의미가 없고, 그 밤은 1위를 린치하는 시간이 되기 때문이다.
- 그래서 **밤은 총 9번**이다. §2의 선택도 9번이다.
- 수치는 전부 튜닝 대상. 페이즈 길이는 데이터 테이블(`DT_DayPhase`)로 뺀다.
- **다만 총합 60~70분은 튜닝 대상이 아니라 제약이다.** 일수나 페이즈를 늘릴 때 이 표를 먼저 다시 계산한다.

**밤에만 남의 카페에 들어갈 수 있다.** 낮에는 침입 불가 — 낮에는 운영에만 집중하게 하고, 밤에만 긴장을 몰아주기 위해서.

## 5. 맵과 카페 위치

- 하나의 공유 월드. 스타크래프트 방식으로 **고정된 시작 지점 후보(Start Location) N개** 중에서 무작위 배정.
  - 맵마다 후보 지점은 미리 정해져 있고, 매 판 그중 인원 수만큼 뽑는다.
  - 지점 간 거리·좀비 구역까지의 거리는 균등하게 설계한다.
- **게임 시작 시 서로의 위치를 모른다.** 자기 카페 위치만 안다.
- 남의 위치를 아는 방법:
  1. 밤에 직접 돌아다니다 발견
  2. 카페 주인을 죽이고 떨어진 **위치 카드(Location Card)** 획득

### 위치 카드는 영구가 아니다 — 유효기간 3일

- 획득한 위치 카드는 **3일 후 소멸**한다. 소멸하면 그 카페 위치를 다시 모르게 된다.
- 영구 공개면 **한 번의 죽음이 남은 판 전체를 결정한다.** 10일 중 2일차에 죽은 사람은 8일을 매일 털리며 보낸다.
- 3일이면 압박은 그대로 주면서 회복 여지가 남는다. 카드를 쥔 쪽도 "3일 안에 써야 한다"는 시한이 생겨 습격이 미뤄지지 않는다.

### 이사 (카페 이전)

- 낮에 **골드를 지불하고 시작 지점 후보 중 빈 곳으로 이전**할 수 있다.
- 비용: 골드 + **그날 낮 매출의 절반** (이사하는 동안 영업 못 함).
- 효과: **자신을 가리키는 위치 카드가 전부 즉시 무효화된다.**
- 뒤처진 플레이어의 탈출구다. 비싸지만 존재해야 한다.
- 맵 중앙에 **좀비 구역(Zone)** 이 있다. 중앙에 가까울수록 좋은 전리품, 강한 좀비.

## 6. 낮 — 카페 운영

### 6.1 제조 — 오버쿡 방식

**낮의 조작감은 오버쿡(Overcooked)이다.** 메뉴를 고르는 게임이 아니라, 좁은 주방을 뛰어다니며 동선을 관리하는 게임이다.

- 커피 한 잔은 **스테이션을 순서대로 거쳐야** 완성된다. 예: `원두 선반 → 그라인더 → 에스프레소 머신 → 스팀/토핑 → 서빙대`
- 각 스테이션은 상호작용 후 **시간이 걸린다.** 그동안 플레이어는 다른 잔을 진행할 수 있다. 여러 주문이 항상 겹친다.
- **방치하면 망친다.** 그라인더에 오래 두면 과분쇄, 머신에 오래 두면 탄다 → 폐기하고 처음부터.
- 손님마다 **대기 게이지.** 다 차면 나가고, 그날 단골 획득도 날아간다.
- 조작은 `이동 + 상호작용 1키 + 들기/놓기` 만. 복잡한 게 아니라 **바쁜 것**이 목표다.
- **시설 투자가 곧 난이도다.** 좌석과 머신을 늘리면 매출도 오르지만 동선이 길어지고 주문이 더 겹친다. 감당 못 할 만큼 키우면 오히려 손해.

> 오버쿡과 다른 점: **협동이 아니라 각자 자기 카페를 혼자 돌린다.** 남의 주방은 안 보인다. 그래서 밤에 훔쳐보러 갈 이유가 생긴다.

### 6.2 손님 기믹 (핵심)
손님은 **선호 태그**를 가지고 등장한다. (예: `Taste.Sweet`, `Taste.Bitter`, `Origin.Ethiopia`, `Rare.PreWar`)

- 내 카페에 **등록된 레시피 중 손님의 선호 태그와 맞는 것**이 있으면:
  - 판매 골드 배수 증가 (기본 ×1.5 ~ ×3, 레시피 희귀도에 비례)
  - 만족한 손님은 다음 날 **단골**로 재방문 (고정 수요 확보)
- 맞는 레시피가 없으면 기본 커피만 팔거나, 손님이 그냥 나간다.

즉 **레시피는 곧 매출이고, 레시피는 밤에만 구할 수 있다.** 이것이 낮과 밤을 묶는 고리다.

### 6.3 레시피 등록
- 획득한 레시피는 카페 메뉴판에 **등록(Register)** 해야 판매 가능.
- 등록 슬롯은 제한(초기 3칸, 시설 투자로 확장). 무엇을 올릴지가 선택이 된다.
- **등록된 레시피는 습격당하면 훔쳐질 수 있다.** 좋은 걸 올릴수록 매출도 오르고 표적도 된다.

### 6.4 시설 투자
골드로 구매. 전부 데이터 테이블로 관리.

| 분류 | 예시 | 효과 |
|---|---|---|
| 매출 | 좌석 증설, 로스터 업그레이드 | 손님 수/객단가 증가 |
| 보관 | 금고, 창고 | 습격 시 도난량 감소, 재료 상한 증가 |
| 방어 | 자물쇠, 함정, 경보 | 침입 지연·피해·알림 |
| 원정 | 배낭, 무기, 부츠 | 밤 파밍 효율 |

### 6.5 재료와 조달

**기본 원두는 무한이다.** 이것이 파산 방지 바닥이다. 밤에 아무것도 못 건져 와도 다음 날 기본 커피(배수 ×1.0)는 팔 수 있다. 재료가 떨어져 하루를 통째로 날리면 뒤처진 사람이 영영 복구하지 못한다.

**태그 배수는 특수 재료를 써야 발동한다.** 레시피만 있고 재료가 없으면 배수가 안 붙는다. 레시피는 자산, 재료는 소모품이다.

| 재료 | 태그 | 조달 |
|---|---|---|
| 기본 원두 | 없음 | **무한** |
| 시럽·우유·향신료 | `Taste.*` | 밤 파밍(서랍·컨테이너), 행상 |
| 산지 원두 | `Origin.*` | 밤 파밍(창고·좀비 건물), 행상(드물게) |
| 전전 원두 | `Rare.PreWar` | **좀비 구역 중심부 / 랜덤 박스에서만** |

**조달 경로는 둘뿐이다.**

1. **밤 파밍** — 주 조달처.
2. **행상(황혼 20초)** — 매일 황혼에 재고 3칸이 랜덤으로 뜬다. 시세의 2배로 비싸다.
   - 행상을 낮이 아니라 **황혼에 둔 이유**: 3분짜리 낮을 잡아먹지 않고, "이 골드로 재료를 살까 밤에 직접 구하러 갈까"라는 선택을 출격 직전에 만들기 위해서다.
   - 전전 원두는 행상에 절대 안 나온다. 그건 목숨 걸고 가져와야 한다.

- 재료 보유 상한은 창고 시설로 결정된다. 상한 초과분은 버려진다.
- **습격당하면 재료를 실제로 빼앗긴다.** (레시피는 사본이지만 재료는 원본이 사라진다)

### 6.6 매출 공식과 기준 수치

승리 지표가 누적 판매 골드이므로 이 공식이 게임의 척추다.

```
잔당 골드 = 기본가 × 태그 배수 × 시설 배수
하루 매출 = Σ (완성해서 실제로 제공한 잔)
```

**태우거나 손님이 나가면 0이다.** 만든 잔이 아니라 제공한 잔만 센다.

| 항목 | 값 |
|---|---|
| 기본가 | **10골드** |
| 태그 배수 | 일반 ×1.0 / 고급 ×1.5 / 희귀 ×2.0 / **전전 ×3.0** |
| 시설 배수 | `1.0 + 0.1 × 로스터 레벨` (최대 ×1.5) |
| 시작 골드 | **100골드** |

**손님 수 (하루)**

```
손님 수 = 기본 12명 + (좌석 증설 단계 × 4) + 단골 수
```

- **단골**: 만족시킨 손님은 30% 확률로 단골이 된다. 단골은 다음 날 **확정 방문**한다.
- **단골 상한 = 좌석 수.** 자리가 없으면 더 안 늘어난다. 좌석 증설이 곧 단골 상한 증설이다.
- **단골도 떠난다.** 대기 게이지가 다 차서 나가거나 음료를 태우면 그날 단골 1명이 이탈한다.

**기준 매출 (밸런스 목표)**

| 시점 | 하루 매출 | 상태 |
|---|---|---|
| 1일차 | 약 120골드 | 기본 커피 12잔, 완벽 플레이 기준 |
| 5일차 | 400~700골드 | 고급·희귀 레시피 2~3장 운용 |
| 10일차 | 1200~1800골드 | 전전 레시피 + 좌석·로스터 투자 완료 |

> 1일차와 10일차의 격차가 **10배 이상**이어야 "밤에 목숨을 거는" 행동이 정당화된다. 3배 수준이면 아무도 안 나간다.

**주요 가격 (초안, `DT_Facility`)**

| 시설 | 가격 | 효과 |
|---|---|---|
| 좌석 증설 1단계 | 150 | 손님 +4, 단골 상한 +4 |
| 로스터 업그레이드 | 200 | 시설 배수 +0.1 |
| 레시피 슬롯 +1 | 250 | 등록 칸 3 → 4 |
| 금고 | 300 | 습격 시 도난 골드 -50% |
| 배낭 (6 → 9칸) | 200 | 밤 반출량 증가 |
| 자물쇠 | 120 | 침입 검색 시간 +50% |
| 이사 | 400 | 위치 카드 전부 무효화 + 그날 매출 절반 |

## 7. 밤 — 파밍과 습격

### 7.1 좀비 구역 파밍 (PvE, 저위험)
- 컨테이너·시체·건물에서 재료와 **레시피 조각/레시피**를 획득.
- 좀비는 **소리에 반응**한다. 뛰면 위험, 걸으면 안전하지만 시간이 부족하다.
- 밤 종료 전 **탈출 지점(Extraction)** 으로 돌아가야 한다. **못 돌아가면 인벤토리 전부 소실.** (타르코프 규칙)
- 사망 시에도 인벤토리 소실 + 다음 날 낮 능률 페널티.

### 7.2 루팅 — 타르코프 방식

**밤의 루팅은 타르코프를 그대로 가져온다.** 이 부분은 다른 시스템에 양보하지 않는다. 밤이 밤답게 무서운 이유의 전부다.

#### (1) 근접 아웃라인
- 상호작용 가능한 오브젝트(서랍, 캐비닛, 컨테이너, 시체, 랜덤 박스)는 **일정 거리 안에 들어가면 아웃라인이 켜진다.**
- 아웃라인 색으로 상태를 구분한다: **미개봉 / 수색 중 / 이미 턴 것.** 같은 곳을 두 번 뒤지는 낭비를 없앤다.
- 아웃라인은 **손전등 반경 안에서만** 켜진다. 밤 화면은 어둡고, 아웃라인이 사실상 유일한 탐색 단서다.

#### (2) 검색 프로그레스 (핵심)
- 열면 인벤토리 UI가 뜨지만 **내용물이 즉시 보이지 않는다.** 전 슬롯이 가려진 상태로 시작.
- 슬롯마다 **검색 프로그레스 바가 순차로 차면서 아이템이 하나씩 공개된다.**
- **검색 중에는 이동 불가.** 움직이면 중단되고, 다시 열면 공개된 데까지는 유지된다.
- 아이템이 보인 뒤 **가방으로 옮기는 데 또 시간이 든다.** 다 못 챙기고 도망치는 상황이 나와야 정상이다.
- 검색 속도는 장비(가방·도구)로 단축. **원정 시설 투자가 여기서 체감된다.**
- 검색 중에는 **소음이 발생한다.** → 좀비가 온다. 오래 뒤질수록 위험하다.

#### (3) 컨테이너 종류와 랜덤성
| 종류 | 위치 | 슬롯 | 검색 시간 | 주요 산출 |
|---|---|---|---|---|
| 서랍·캐비닛 | 건물 내부 | 1~3 | 짧음 | 재료, 소모품 |
| 컨테이너·상자 | 거리, 창고 | 2~6 | 보통 | 재료, 레시피 조각 |
| 시체 | 좀비 구역 | 랜덤 | 보통 | 장비, 소모품 |
| **랜덤 박스** | 희귀 스폰 | 1 | **김** | 등급 불명. **전전 레시피 주요 스폰** |

- **한 컨테이너에서 나오는 아이템 수는 매번 랜덤이다.** 빈 통도 나온다. 기대값이 아니라 도박이 되게 한다.
- **랜덤 박스**는 열기 전까지 등급을 알 수 없다. 검색 시간이 길어서 "이걸 여기서 여는 게 맞나"를 고민하게 만든다.

#### (4) 건물과 좀비 배치
- **좀비는 맵에 고루 퍼져 있지 않다. 정해진 건물에만 스폰된다.**
- 그래서 **좋은 전리품 = 좀비 있는 건물**이다. 빈 건물은 서랍 몇 개가 전부.
- 건물마다 좀비 밀도·등급이 정해져 있고 밤마다 리스폰된다. **어느 건물이 얼마나 위험한지는 플레이어가 외우는 지식**이 된다.
- 건물 내부는 서랍까지 전부 뒤질 수 있다. 한 건물을 끝까지 터는 데 밤의 상당 시간이 든다 → **한 건물을 깊게 vs 여러 건물을 얕게**의 선택.

### 7.3 전투

**설계 원칙: 총이 흔하면 밤이 총싸움이 되고 루팅 긴장이 죽는다.** 근접이 기본이고, 총은 희귀하면서 시끄럽다.

- **체력 3칸.** 피격 1회 = 1칸. 낮 시작 시 전량 회복, 밤에는 붕대로만 1칸 회복(사용 3초, 이동 불가).
- **조준은 마우스 커서 방향.** 근접은 전방 90° 원호, 총은 직선 히트스캔.
- **백스탭 즉사.** 뒤에서 근접으로 치면 한 방이다. 정면 난투보다 잠입이 유리해야 밤이 조용해진다.
- 좀비에게 맞으면 넉백 + 0.5초 경직. 3마리에게 둘러싸이면 빠져나오지 못한다 — **몰리기 전에 도망쳐야 한다.**

| 무기 | 획득 | 피해 | 소음 반경 | 비고 |
|---|---|---|---|---|
| 파이프·칼 (근접) | 흔함 | 1 (백스탭 즉사) | 3타일 | 기본 장비. 탄약 없음 |
| 권총 | 드묾 | 2 | **20타일** | 탄약 희소. 좀비 대량 유인 |
| 산탄총 | 매우 드묾 | 3 (근거리) | **30타일** | 이기고도 지는 무기 |

> **소음이 곧 밸런스다.** 총으로 이겨도 반경 20~30타일의 좀비가 전부 몰려온다. 총은 "탈출 직전 마지막 한 번" 쓰는 물건이다.

### 7.4 카페 습격 (PvP, 고위험)
- 위치를 아는 남의 카페에 침입.
- 훔칠 수 있는 것: **등록 레시피 사본, 재료, 금고 골드 일부.**
  - 레시피는 원본 삭제가 아니라 **사본 획득**. 상대를 0으로 만들지 않아 역전은 되지만 파괴적이지 않게.
  - 골드는 **누적 판매 골드가 아니라 보유 골드**만 털린다. 승리 지표 자체는 직접 못 뺏는다.
- 주인이 카페에 있을 수도 있다(밤에 출격 안 한 경우). 이때는 PvP 교전.
- **주인을 죽이면 위치 카드가 드랍된다.** → 그 사람의 카페 위치가 영구 공개된다.
- 방어 설비에 걸리면 알림이 뜨고 주인이 복귀할 수 있다.

### 7.5 인벤토리와 사망

**그리드가 아니라 슬롯이다.** 320×180 도트 화면에서 타르코프식 격자 인벤토리는 읽히지 않는다. 칸 개수만으로 압박을 만든다.

| 공간 | 칸 | 사망 시 |
|---|---|---|
| 가방 | 기본 **6** (배낭 투자로 최대 12) | **전부 드랍** |
| 보관 주머니 (Secure Pouch) | **2** | **유지** |

- 아이템 1개 = 1칸. 부피 큰 것(산탄총, 랜덤 박스 전리품)은 2칸.
- **무게는 없다.** 칸 수만으로 충분하다.
- **보관 주머니 2칸이 역전 장치다.** 다 죽어도 전전 레시피 하나는 들고 나올 수 있다. 이게 없으면 한 번의 죽음이 판을 끝낸다.

| 상황 | 가방 | 주머니 | 추가 |
|---|---|---|---|
| 탈출 성공 | 유지 | 유지 | — |
| 탈출 실패 (시간 초과) | **소실** | 유지 | — |
| 사망 | **전부 드랍** | 유지 | 다음 낮 이동·제조 속도 **-20%** |

- **사망한 플레이어의 시체는 컨테이너가 된다.** 검색 프로그레스가 똑같이 적용된다. 죽인 쪽도 그 자리에서 시간을 써야 하므로, 킬 직후가 가장 위험한 순간이다.
- 카페 주인을 죽였을 때만 **위치 카드**가 추가로 드랍된다 (§5, 유효기간 3일).

### 7.6 위험 균형
| 선택 | 기대 수익 | 실패 비용 |
|---|---|---|
| 카페에 남는다 | 0 (방어만) | 없음 |
| 좀비 파밍 | 중 | 인벤토리 소실 |
| 카페 습격 | 고 | 인벤토리 소실 + 위치 노출 |

## 8. 레시피

- 등급: 일반 / 고급 / 희귀 / **전전(戰前) 레시피**
- 전전 레시피는 좀비 구역 중심부에서만 나온다. 배수와 단골 확보량이 압도적.
- 레시피는 **태그 조합**으로 정의한다. (`Taste.*`, `Origin.*`, `Rare.*`)
  - 손님 시스템은 구체 레시피 이름을 절대 알지 않는다. 태그만 대조한다.
  - 새 레시피 추가 = 데이터만 추가. 시스템 코드 수정 없음.

### 8.1 레시피 조각 (Fragment)

- **같은 등급 조각 3개 = 레시피 1장.** 등급이 섞이면 조합되지 않는다.
- 조각은 등급 태그를 갖는다 (`Fragment.Rare`, `Fragment.PreWar` …).
- 조합은 **낮에 카페에서** 한다. 3초 소요. 낮에 하게 한 이유는 밤 3분을 조합에 쓰게 하지 않기 위해서다.
- **조각은 사본이 아니라 실물이다.** 습격당하면 실제로 빼앗긴다.
  - 완성 레시피는 훔쳐가도 사본이라 원본이 남지만, 조각은 사라진다.
  - 그래서 **조각을 오래 쥐고 있는 것이 가장 위험하다.** "2개 모았는데 하나만 더" 상태가 이 게임에서 제일 초조한 순간이 되게 한다.

## 9. 오브젝트 데이터 (능력치 골격)

수치는 전부 초안이다. 중요한 것은 **표로 뽑히는 형태**라는 점 — 그대로 ScriptableObject 필드가 된다.

### 9.1 플레이어

| 항목 | 값 |
|---|---|
| 체력 | 3칸 |
| 걷기 | 2.0 타일/s (소음 2타일) |
| 뛰기 | 4.0 타일/s (소음 **8타일**) |
| 검색 중 | 이동 불가 (소음 4타일) |
| 가방 | 6칸 (최대 12) / 주머니 2칸 |
| 손전등 반경 | 5타일 (아웃라인이 켜지는 범위) |

### 9.2 좀비 — 2종

| | 배회자 (Shambler) | 추격자 (Runner) |
|---|---|---|
| 체력 | 3 | 2 |
| 이동속도 | 1.5 타일/s | **3.5 타일/s** |
| 공격력 | 1칸 | 1칸 |
| 공격 간격 | 1.5초 | 1.0초 |
| **소리 감지 반경** | 8타일 | **12타일** |
| **시야 감지 반경** | 3타일 (전방 90°) | **8타일** (전방 90°) |
| 추적 포기 | 6초 | 10초 |
| 넉백 | 0.5초 경직 | 0.5초 경직 |

**행동 규칙 (구체 숫자, 이게 없으면 좀비가 가만히 있는다)**

1. **기본 상태 = 배회.** 스폰 지점 반경 4타일 안을 3~6초 간격으로 무작위 이동.
2. **소리를 들으면** → 소리 발생 좌표로 직행. 도착 후 **3초 배회**하며 탐색.
3. 탐색 중 플레이어가 시야에 들어오면 → **추격**. 접촉 시 공격.
4. 시야에서 놓치면 → 마지막 목격 지점으로 이동 후, 위 표의 **추적 포기 시간**이 지나면 스폰 지점으로 복귀.
5. 소리는 **가장 최근 것 하나만** 쫓는다. 큐를 쌓지 않는다 (3분짜리 밤에 좀비가 영원히 헤매면 안 된다).

**소음 반경 일람** — 좀비 AI의 유일한 입력이다.

| 행동 | 반경 |
|---|---|
| 걷기 | 2타일 |
| 검색 중 | 4타일 |
| 근접 공격 | 3타일 |
| 문 열기 | 6타일 |
| **뛰기** | 8타일 |
| **권총** | 20타일 |
| **산탄총** | 30타일 |

### 9.3 건물 등급과 좀비 스폰

| 등급 | 위치 | 좀비 | 컨테이너 | 랜덤 박스 |
|---|---|---|---|---|
| 빈 건물 | 외곽 | **0** | 서랍 2~4 | 없음 |
| 하급 | 외곽~중간 | 배회자 3 | 서랍 4 + 상자 1 | 5% |
| 중급 | 중간 | 배회자 4 + 추격자 2 | 서랍 6 + 상자 2 | 20% |
| **중심부** | 좀비 구역 중앙 | 배회자 7 + 추격자 5 | 서랍 8 + 상자 4 + 시체 2 | **60%** |

- **리스폰은 밤 시작 시 1회 전량.** 밤 도중에는 재스폰하지 않는다.
  - 3분짜리 밤에 재스폰이 있으면 "이 건물은 정리했다"는 학습이 무의미해지고, 탈출 경로 확보가 불가능해진다.
- 건물 등급은 맵에 고정 배치된다. **어느 건물이 위험한지는 판이 거듭되며 플레이어가 외우는 지식**이 되어야 한다.

### 9.4 컨테이너

| 종류 | 슬롯 | 검색 시간/슬롯 | 산출 |
|---|---|---|---|
| 서랍·캐비닛 | 1~3 | 1.0초 | 재료, 소모품 |
| 상자·컨테이너 | 2~6 | 1.5초 | 재료, 레시피 조각 |
| 시체 | 2~4 | 1.5초 | 장비, 탄약, 붕대 |
| **랜덤 박스** | 1 | **6.0초** | 등급 불명. 전전 레시피 주요 스폰 |
| 플레이어 시체 | 죽은 자의 가방 칸 수 | 1.5초 | 그가 들고 있던 전부 |

- 슬롯 수는 **매번 랜덤**이며, 슬롯이 비어 있을 수도 있다.
- 검색 시간은 배낭 시설로 최대 **-30%** 단축.
- 자물쇠가 걸린 카페 컨테이너는 검색 시간 **+50%**.

### 9.5 손님

| 항목 | 값 |
|---|---|
| 하루 손님 수 | `12 + (좌석단계 × 4) + 단골 수` |
| 등장 간격 | 낮 3분에 균등 분산 |
| 대기 게이지 | **25초** (다 차면 이탈) |
| 선호 태그 | 1개 (`Taste.*` / `Origin.*` / `Rare.*`) |
| 단골 전환 | 만족 시 **30%** |

## 10. 조작 체계

**같은 키가 낮과 밤에서 다른 일을 한다.** 낮은 오버쿡(빠른 연타), 밤은 타르코프(홀드와 정지)라 요구가 정반대다. 컨텍스트로 나눈다.

| 키 | 낮 (운영) | 밤 (침투) |
|---|---|---|
| `WASD` / 방향키 | 이동 | 이동 |
| `Shift` | **대시** (짧은 쿨다운, 이득) | **뛰기** (소음 8타일, 위험) |
| `E` (탭) | 상호작용 — 스테이션 조작, 들기/놓기 | 아이템 줍기 |
| `E` (홀드) | — | **검색 시작** (떼면 중단) |
| 마우스 좌클릭 | 서빙 대상 지정 | **공격** |
| 마우스 우클릭 | — | 조준 (총기) |
| `F` | — | **손전등 on/off** |
| `Tab` | 메뉴판 / 시설 구매 | **가방** |
| `Q` | 들고 있는 잔 버리기 | 아이템 버리기 |
| `M` | 미니맵 확대 | 미니맵 확대 |
| `Esc` | 일시정지 메뉴 | 일시정지 메뉴 |

**주의해서 설계한 지점**

- **`E`는 낮에 탭, 밤에 홀드.** 같은 키지만 입력 방식이 달라 오폭이 없다. 밤에 탭하면 줍기, 홀드하면 검색이다.
- **`Shift`가 낮에는 이득이고 밤에는 위험이다.** 이건 버그가 아니라 의도다. 낮의 습관대로 밤에 뛰면 좀비가 온다.
- **카메라 이동키를 따로 두지 않는다.** 카메라는 항상 플레이어를 따라간다. `WASD`가 카메라와 명령을 동시에 건드리는 사고를 원천 차단한다.
- 게임패드는 MVP 범위 밖.

## 11. 화면 구성 (UI)

**논리 해상도 320×180이 제약이다.** HUD가 화면을 잡아먹으면 게임이 안 보인다. **상·하단 각 20px 이내**로 묶는다 (합쳐도 세로의 22%).

### 11.1 낮 HUD

| 위치 | 요소 |
|---|---|
| 상단 좌 | **주문 큐** — 최대 4개, 아이콘 + 선호 태그 |
| 상단 우 | 보유 골드 / 오늘 매출 / 남은 시간 |
| 손님 머리 위 | **대기 게이지** (25초, 3단계 색상) |
| 플레이어 머리 위 | 들고 있는 잔의 상태 (진행/완성/탐) |
| 하단 | 없음 — 카페 바닥을 최대한 보여준다 |

### 11.2 밤 HUD

| 위치 | 요소 |
|---|---|
| 상단 좌 | **체력 3칸** |
| 상단 우 | **탈출까지 남은 시간** (30초 이하 시 붉게 점멸) |
| 하단 | **가방 슬롯 바** (6~12칸, 아이콘만) |
| 하단 좌 | **소음 인디케이터** — 내 소음 반경을 파문 크기로 표시 |
| 화면 가장자리 | 손전등 비네트 (반경 5타일 밖은 어둠) |
| 상단 배너 | **습격 알림** — "당신의 카페에 침입자" + 방향 화살표 |

> **소음 인디케이터가 밤 UI의 핵심이다.** 소리가 게임의 주 규칙인데 눈에 안 보이면 플레이어는 규칙을 배우지 못한다.

### 11.3 검색 UI

- 화면 **중앙 패널**, 슬롯을 세로로 나열.
- 슬롯마다 프로그레스 바가 위에서 아래로 순차 진행.
- 공개 전 슬롯은 `?` 실루엣, 공개 후 아이콘 표시.
- 패널을 열어도 **주변이 보여야 한다** — 패널은 화면 폭의 40%를 넘지 않고 반투명.

### 11.4 결산 / 종료

- 일일 결산: 전체 화면. 4인의 오늘 판매 수 / 오늘 골드 / **누적 골드 / 순위**.
- 레시피 목록과 카페 위치는 표시하지 않는다 (§3).
- 최종 결산(10일차): 누적 골드 그래프 10일치 + 승자 연출.

## 12. 기술 스택과 넷코드 (Unity)

### 12.1 스택

| 항목 | 선택 | 이유 |
|---|---|---|
| 엔진 | **Unity 6 (또는 2022 LTS)** | — |
| 렌더 | **URP 2D Renderer** | 2D 라이트로 밤 손전등·비네트를 그대로 구현 |
| 픽셀 | **Pixel Perfect Camera** — Reference Resolution `320×180`, PPU `32`, Upscale Render Texture ON | 정수 배율 유지 (아트컨셉 §3) |
| 넷코드 | **Netcode for GameObjects (NGO)** + 데디케이티드 서버 빌드 | 서버 권위 |
| 데이터 | **ScriptableObject** (레시피·시설·좀비·컨테이너·손님) | CSV → SO 임포터로 밸런스 일괄 수정 |
| 좀비 AI | 자체 FSM (배회 / 조사 / 추격 / 복귀) | NavMesh 없이 타일 A* — 아이소 타일맵이라 그리드가 이미 있다 |

- **로직과 렌더를 분리한다.** 시뮬레이션(경제·판매·검색·좀비 FSM)은 `MonoBehaviour` 바깥의 순수 C# 클래스로 두고, `MonoBehaviour`는 입력과 표시만 담당한다. 에디터 없이 **headless 테스트가 가능해야** 완료 기준(§15)을 자동으로 돌릴 수 있다.

### 12.2 넷코드 원칙

- **서버 권위(Server Authoritative).** 골드·판매·인벤토리·레시피 소유권은 **서버에서만** 변경한다. 클라이언트는 `ServerRpc`로 의도만 보낸다.
- 페이즈(낮/황혼/밤/결산) 전환은 **`NetworkVariable<DayPhase>` 단일 값**으로 관리한다. 클라이언트는 이 값을 보고 UI만 바꾼다.
- **남의 카페 정보는 복제하지 않는다.**
  - 레시피 목록·금고·조각은 `NetworkVariable`에 올리지 않는다.
  - 침입해서 실제로 열었을 때만, 서버가 **그 클라이언트에게만** `ClientRpc`(targeted)로 내려준다.
  - 카페 내부 오브젝트는 `NetworkObject.CheckObjectVisibility`로 **소유자에게만 스폰**한다.
  - → 메모리 스캔으로 남의 레시피를 훔쳐보는 것을 원천 차단한다.
- **위치 카드도 동일.** 카드를 획득한 클라이언트에게만 좌표를 내려준다. 유효기간 만료 시 서버가 회수한다.
- **검색 프로그레스는 서버가 센다.** 클라이언트는 바만 그린다. 클라 타이머를 믿으면 검색 시간이 0이 된다.
- **예측은 이동만.** 이동은 클라이언트 예측 + 서버 보정. 경제·루팅·전투 판정은 예측하지 않는다 (되돌림이 더 큰 문제를 만든다).
- 좀비는 **서버에서만 시뮬레이션**하고 위치만 복제한다.

## 13. 성능 상한

**나중에 최적화하지 않는다. 처음부터 이 안에서 만든다.**

**최악 장면 정의:** 4인 세션, 한 클라이언트 화면에 좀비 12기 + 손님 20명 + 파티클 100개 + 카페 가구 40개가 동시에 보이고, 미니맵이 갱신되는 순간.

| 항목 | 상한 | 지키는 법 |
|---|---|---|
| 목표 프레임 | **60fps** (최악 장면에서 55 이상) | 아래를 지키면 자연히 달성 |
| 드로우콜 | **≤ 60** | **Sprite Atlas 1장**으로 전 스프라이트 통합. 아틀라스가 쪼개지면 즉시 깨진다 |
| 동시 SpriteRenderer | **≤ 300** | 화면 밖 오브젝트 비활성화 |
| 2D 라이트 | **≤ 8** (밤) | 손전등 1 + 카페 창 몇 개. 라이트가 2D URP의 최대 비용 |
| 서버 동시 활성 좀비 | **≤ 60** (맵 전체) | 플레이어 반경 밖은 FSM 틱을 1/4로 |
| 서버 틱레이트 | **30Hz** | — |
| `NetworkVariable` 갱신 | **≤ 15Hz** | 위치는 보간 |
| 클라 1인당 대역 | **≤ 32KB/s** | 4인 세션에서 가장 먼저 터질 곳 |
| GC Alloc | **밤 3분 동안 0** | 좀비·투사체·파티클 전부 오브젝트 풀 |

> 물량이 상한을 넘으면 스프라이트를 정교하게 만들 게 아니라 **개수를 줄인다.**

## 15. MVP 범위와 완료 기준

10일이 아니라 **2인 3일**로 먼저 돌린다. (3일 = 약 20분)

### 15.1 범위

- 낮 / 황혼 / 밤 / 결산 페이즈 순환 (서버 권위)
- 카페 1종, 제조 스테이션 3종, 손님 태그 매칭 1종
- 좀비 구역 1개, 건물 2채(빈 건물 / 하급), 탈출 지점 1개
- 좀비 1종(배회자), 근접 무기만
- 컨테이너 2종(서랍, 상자), 검색 프로그레스
- 카페 침입 + 레시피 사본 훔치기
- 일일 결산 순위 UI

**뒤로 미루는 것:** 추격자, 총기, 랜덤 박스, 레시피 조각, 위치 카드, 이사, 행상, 방어 설비, 단골, 시설 대부분.

### 15.2 완료 기준 (각 항목이 테스트 하나가 된다)

**페이즈**
- [ ] 낮 3분이 지나면 자동으로 황혼으로 넘어가고, 모든 클라이언트의 UI가 동시에 바뀐다
- [ ] 3일차 낮이 끝나면 밤 없이 최종 결산이 뜬다
- [ ] 결산 화면에 2인의 누적 골드가 내림차순으로 표시된다

**낮 — 제조**
- [ ] 원두 선반 → 그라인더 → 머신 → 서빙대 순서로 조작하면 커피 1잔이 완성된다
- [ ] 순서를 건너뛰면 다음 스테이션이 반응하지 않는다
- [ ] 머신에 8초 이상 방치하면 잔이 `탐` 상태가 되고, 제공해도 골드가 0이다
- [ ] 손님 대기 게이지가 25초에 다 차면 손님이 나가고 골드가 들어오지 않는다
- [ ] 손님의 선호 태그와 맞는 레시피로 제공하면 기본가 10골드에 배수가 적용된다

**밤 — 루팅**
- [ ] 컨테이너 2타일 안에 들어가면 아웃라인이 켜지고, 벗어나면 꺼진다
- [ ] 이미 턴 컨테이너는 다른 색 아웃라인으로 표시된다
- [ ] `E`를 홀드하면 슬롯 프로그레스가 차고, 떼면 즉시 멈춘다
- [ ] 재진입하면 이미 공개된 슬롯은 그대로 공개 상태다
- [ ] 컨테이너를 10번 열면 나온 아이템 수가 매번 같지 않다 (빈 통 포함)
- [ ] 가방 6칸이 다 차면 더 줍히지 않는다

**밤 — 좀비**
- [ ] 배회자는 플레이어가 없을 때 스폰 지점 4타일 안을 계속 움직인다
- [ ] 8타일 안에서 `Shift`로 뛰면 배회자가 그 지점으로 이동해 온다
- [ ] 걷기(2타일)만으로는 8타일 거리의 배회자가 반응하지 않는다
- [ ] 시야에서 벗어나 6초가 지나면 배회자가 스폰 지점으로 복귀한다
- [ ] 뒤에서 근접 공격하면 배회자가 한 방에 죽는다
- [ ] 빈 건물에는 좀비가 0마리, 하급 건물에는 3마리가 스폰된다

**밤 — 탈출과 사망**
- [ ] 밤 3분 안에 탈출 지점에 도달하면 가방이 유지된다
- [ ] 도달하지 못하면 가방이 비고 보관 주머니 2칸은 남는다
- [ ] 사망하면 그 자리에 시체가 남고, 다른 플레이어가 검색 프로그레스로 열 수 있다
- [ ] 사망한 다음 날 낮의 이동 속도가 20% 느리다

**습격**
- [ ] 상대 카페에 침입해 등록 레시피를 훔치면 **양쪽 모두** 그 레시피를 갖는다
- [ ] 훔친 골드만큼 상대의 보유 골드가 줄고, **누적 판매 골드는 변하지 않는다**

**넷코드 / 치트 방어**
- [ ] 침입하지 않은 상태에서 상대의 레시피 목록이 클라이언트 메모리에 존재하지 않는다
- [ ] 클라이언트에서 골드 값을 조작해도 서버 결산에 반영되지 않는다
- [ ] 검색 시간을 클라이언트에서 0으로 바꿔도 서버가 아이템을 주지 않는다

**성능**
- [ ] 최악 장면(§13)에서 55fps 이상을 유지한다
- [ ] 드로우콜이 60을 넘지 않는다
- [ ] 밤 3분 동안 GC Alloc이 0이다
- [ ] Unity 콘솔에 에러가 0건이다

## 16. 미결 사항

- ~~시점 확정~~ → **쿼터뷰로 확정.** 인물은 남동·남서 2벌 + 미러로 4방향.
- ~~한 판 길이~~ → **10일 / 약 63분으로 확정** (§4).
- ~~타깃 엔진~~ → **Unity 확정** (§12).
- **인원 수(2~4인) 확정** — 4인이면 습격 대상이 늘어 밤이 재밌지만, 맵과 좀비 구역을 그만큼 넓혀야 한다. 밤이 3분이라 **이동 거리가 곧 밸런스**다. 맵 크기와 함께 결정.
- **검색 시간 vs 밤 3분** — 하급 건물 한 채(서랍 4 + 상자 1)를 다 터는 데 이론상 약 `4×2×1.0 + 1×4×1.5 = 14초`. 이동을 포함하면 건물당 40~60초. **밤 3분에 건물 2~3채가 한계**라는 뜻이다. 이 숫자가 맵 밀도를 결정한다.
- **오버쿡식 제조의 스테이션 수** — 혼자 주방을 돌리므로 `3~4단계`가 상한. 낮이 3분으로 줄어 4단계는 과할 수 있다. MVP에서 3단계로 검증.
- **최하위 구제 장치** — 10일로 줄고 위치 카드 유효기간 3일 + 이사가 생겨 이전 버전보다 완화됐다. 추가 장치가 더 필요한지는 플레이 테스트 후 판단.
- **아트컨셉 미규격** — 아웃라인 3색, 검색 패널, 소음 인디케이터 (§14).

## 17. 버전 규칙

- 기획서는 `Plan/Blood&Bean_기획서_v{major}.{minor}.md` 로만 저장한다. 다른 폴더에 두지 않는다.
- 수정할 때 **기존 파일을 덮어쓰지 않고** 새 버전 파일을 만든다. 이전 버전은 그대로 남긴다.

- 최신본 = 버전 번호가 가장 높은 파일. 별도 인덱스 파일은 두지 않는다.
- 새 파일 상단 인용구의 `**vX.Y** · 날짜 · 이전 버전` 줄과 아래 변경 이력을 같이 갱신한다.
