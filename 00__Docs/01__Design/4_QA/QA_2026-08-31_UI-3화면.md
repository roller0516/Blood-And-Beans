## 치명

### C-1. 16:9가 아닌 종횡비에서 화면 하단·우측 UI가 잘려 조작 불가

- **파일:** `Assets/Scripts/Client/UI/UITheme.cs:41-47` (`At` — 앵커·피벗 `(0,1)` 고정 + 절대 `sizeDelta`)
  → 이를 쓰는 `UICharacterSelectScreen` / `UIDaySettlementScreen` / `UIFacilityUpgradeScreen` 전체
  → 프리팹 3개의 CanvasScaler `m_MatchWidthOrHeight: 0.5`
- **원인:** 모든 요소를 좌상단 앵커 + 절대 크기로 못 박았다. CanvasScaler가 `MatchWidthOrHeight = 0.5`라
  16:9를 벗어나는 순간 캔버스 논리 크기가 1920×1080에서 어긋나고, 절대 좌표가 그대로 화면 밖으로 나간다.
- **실측**

  | 종횡비 | 캔버스 논리 크기 | 잘리는 영역 | 사라지는 것 |
  |---|---|---|---|
  | 21:9 (2560×1080) | 2217.03 × 935.31 | 하단 144.7px | 캐릭터 선택 푸터(`뒤로`·`선택 완료`) 전체, 2행 카드 이름·태그, 업그레이드 `적용하고 밤으로`, 정산 푸터·`DEBT CARRIED` |
  | 4:3 (1440×1080) | 1662.77 × 1247.08 | 우측 257.2px | 대기 라벨·타이머, `선택 완료` 절반, **4번째 예보 카드**, **3번째 인기 재료**, CAFE LAYOUT 우측(오븐·싱크대·적용 버튼) |
  | 16:10 (1920×1200) | 1821.47 × 1138.42 | 우측 98.5px | 위 요소들 부분 잘림 |

- **영향:** 21:9에서 캐릭터 확정·업그레이드 적용이 **불가능**해 게임 진행이 막힌다.
  4:3에서는 기획서 5.6 예보 4종 중 4번째, 5.6.1 인기 재료 2~3종 중 3번째가 사용자에게 보이지 않아 정보가 누락된다.
- **재현**
  ```
  unity command editor_play
  unity command eval --code 'UnityEditor.PlayModeWindow.SetCustomRenderingResolution(2560u,1080u,"QA 21:9");'
  unity command eval --code 'var s=UIManager.Instance.ReplaceScreen<UICharacterSelectScreen>(); s.Bind(...);'
  unity command capture_game_view --source screen --width 2560 --height 1080
  ```
- **수정 방향:** 배경은 스트레치 앵커로, 화면 가장자리에 붙는 요소(타이머·푸터 버튼·우측 패널)는
  해당 모서리 앵커로. 최소한 `MatchWidthOrHeight`를 콘텐츠 기준 축에 맞추고 세이프 영역을 잡아야 한다.

## 높음

### H-1. 배경(Backdrop)이 뷰포트를 덮지 못해 UI 뒤로 게임 월드가 비친다

- **파일:** `UICharacterSelectScreen.cs:52`, `UIDaySettlementScreen.cs:86`, `UIFacilityUpgradeScreen.cs:48`
  — 모두 `UITheme.Box(transform, "Backdrop", UITheme.Ink, 0f, 0f, 1920f, 1080f)`
- **실제:** 1920×1080 고정 크기라 캔버스가 그보다 크면 남는 영역이 투명해진다.
  4:3에서 하단 167.1px, 16:10에서 하단 58.4px, 21:9에서 우측 297px에 카페 씬이 그대로 비친다.
- **비고:** C-1과 원인이 같다. 같이 고쳐야 한다.

### H-2. 전환 페이즈 정산 화면이 어디서도 열리지 않는다

- **기획서 근거:** 4장 표 — `전환 (정산) | 10초 | 매출/임대료 결과, 순위, 업그레이드 적용, 내일의 손님 예보`
- **파일:** `UIDaySettlementScreen.cs:180` `Bind` / `:209` `SetRemaining` — 완성돼 있고 호출자 0.
  `MatchFlow.cs:141-144`의 `Update`가 여는 것은 `SyncLootPopup` / `SyncReturnPopup` / `SyncResultPopup` 셋뿐.
- **실제:** 전환 10초에 뜨는 것은 귀환 팝업과 HUD 텍스트 두 줄(`MatchHudPresenter.cs:119-125`)뿐.
  순위·매출·임대료가 없다. 4장이 요구한 4가지 중 예보 하나만 충족.
- **비고:** 프리팹·스크립트·`UIManager` 등록까지 다 돼 있고 `Push`만 없다. **미배선이지 오배선이 아니다.**

### H-3. 임대료·부채·미납 페널티가 플레이어에게 한 번도 표시되지 않는다

- **기획서 근거:** 3.2(임대료·부채 이월), 3.3(페널티 3단계), 4장(전환에 "매출/임대료 결과")
- **파일:** `Economy/TransitionLedger.cs:43` `RentOf(int team)` — **호출자 0건**
- **실제:** 페널티는 **실제로 걸린다.** 소비자 코드가 전부 실재한다 —
  `Station.cs:121`(제작 1.10배), `TransitionLedger.cs:112-116`(머신 불통·그릇 파손),
  `FogOfWar.cs:164`(시야 0.7), `ItemBox.cs:352`(개봉 1.5배), `PlayerInventory.cs:99`(무게 밴드 이동).
  그런데 표시가 없어 **원인 불명의 버그로 체감된다.**
- **비고:** H-2와 같은 화면 하나를 꽂고 임대료 값을 넘기면 둘 다 닫힌다.

### H-4. 최종 결산 팝업에서 빠져나갈 수단이 없다

- **파일:** `Client/UI/UIMatchResultPopup.cs:35` `BlocksPlayerInput => true`, `Build()`(107–131)에 버튼 없음.
  `MatchFlow.cs:155-176`이 한 번 띄우고 `resultPopupOpen = true`로 다시 열지 않는다.
- **기대:** 목업 8번의 `ESC 로비로` / `↵ 한 판 더`
- **실제:** 입력이 잠긴 팝업이 뜨고 닫을 방법이 코드 어디에도 없다. 판이 끝나면 매치에서 못 나온다.
- **부수:** 목업 8번 `FINAL RANKING`은 카페 이름을 쓰는데 구현은 `Team 0` 숫자만 쓴다(`:92`).

### H-5. 업그레이드 설치 버튼이 클릭 후에도 계속 눌린다 — 서버 연결 시 재료 이중 차감 통로

- **기획서 근거:** 8장 — 업그레이드 재료는 3등급 박스에서만 나온다(희소 자원)
- **파일:** `UIFacilityUpgradeScreen.cs:186` — `UIButtons.Wire(installButtons[i], () => install?.Invoke(id));`
  `Bind`가 `parts`를 로컬에서 깎지 않는 것은 **옳지만**, 버튼 상태도 갱신하지 않는다.
- **실제:** 화면이 무제한 호출을 허용한다. 지금은 호출자가 없어 잠재적이지만, 서버 RPC를 붙일 때
  멱등 가드가 없으면 연타 = 이중 설치·이중 차감.
- **권고:** 서버 RPC는 `[Rpc(SendTo.Server)]` + `p.Receive.SenderClientId` → `Cafe.SameTeamServer`
  → `if (installed[id]) return;` → `if (parts < cost) return;` 순서. `Day/Station.cs:82-100` 패턴 그대로.

## 기획 확정이 먼저 필요한 항목 (코드로 손대면 안 됨)

### P-1. 캐릭터 선택 화면의 밤 슬롯 — 패시브인가 액티브인가

- 기획서 9.1: 밤 패시브 후보 표 **전체가 취소선** + "**밤은 액티브로 고정**". 9.2에 쿨타임 액티브 6종.
- 기획서 11장: "캐릭터 능력은 전부 패시브이므로 스킬 키가 없다" ← **9.2와 기획서 내부 모순**
- 목업 2번: `NIGHT PASSIVE` + 밤 패시브 8종 (v2.5 이전 상태)
- 구현: 밤 소제목을 `Bind` 인자로 빼서 판단 보류. **다만 `UICharacterSelectScreen.cs:266`에
  "발동 키 없는 상시 패시브"를 하드코딩해 유예 처리에 구멍이 있다.**

### P-2. 예보가 밤에 닿지 않는다 — "내일"의 지시 대상

- 기획서 5.6.3 절 제목: "**예보가 밤에 주는 것**". 5.6: "전환 페이즈에 **다음 날**의 손님 구성과 인기 재료가 공개된다"
- 구현(`TransitionLedger.cs:78, 134-135`): 밤이 **끝난 뒤** 예보를 뽑아 **바로 다음 낮**에 소비.
  파밍 중에 인기 재료를 알 창이 없다.
- 코드는 "전환 직후의 낮 = 내일", 5.6.3은 "다음 사이클의 낮 = 내일"로 읽힌다.
- 영향: 5.6.1이 인기 재료를 굳이 "그날 밤 리젠 풀"로 제한한 이유(밤의 선택과 낮의 값을 잇는 것)가 사라진다.

### P-3. 임대료를 내고 남은 돈의 처리 — 기획 공백

- 기획서 3.2는 **부족분**의 이월만 규정하고 **잉여**에 대한 규정이 없다.
- 구현(`TransitionLedger.cs:92-93`): 잉여는 저장되지 않고 소멸한다.
- 결과: "하루라도 못 팔면 무조건 미납 → 페널티"가 되어 3.3 난이도가 의도보다 가파를 수 있다.
- 승패 지표가 누적 매출이라 승패 자체에는 영향 없다.

### P-4. `PlayerCarry.view`의 복제 범위 — 설계 판단 필요

- 기획서 3.1: "각 팀의 현재 매출만 공개된다. **보유 재료·설비·캐릭터는 비공개.**"
- 파일: `Player/PlayerCarry.cs:35` — `NetworkVariable<CarryView> view` 읽기 권한이 기본값 `Everyone`
- 쓰기 권한은 `Server`로 **옳다**(NGO `NetworkVariableBase.cs:220-225` 대조). 문제는 읽기.
- 카페는 `MatchDirector.cs:192`의 `SpawnWithObservers = false` + 팀별 `NetworkShow`로 격리되지만,
  플레이어 오브젝트는 밤 대시 견제(6.6) 때문에 전원에게 보여야 해서 그 보호가 없다.
- 이 저장소가 이미 아는 해법: `Night/PlayerInventory.cs:25-33`이 같은 이유로 `ReadPermission.Owner`를 명시.
- **함정:** `Owner`로 바꾸면 팀원 손 표시 기능이 죽는다. NGO 2.13에 팀 단위 read 권한이 없다.
  제대로 하려면 `TransitionLedger.cs:151`의 `[Rpc(SendTo.SpecifiedInParams, InvokePermission = RpcInvokePermission.Server)]`
  방식으로 팀원에게만 보내야 한다. **임의로 고치지 말 것.**

| `UIDaySettlementScreen` | 안 됨 | **결함(H-2)** — 13장 「넣는 것」에 예보·인기 재료 보너스·순위 티커·임대료 1단계가 있다 |

4장이 전환에 "업그레이드 적용"을 두었지만 13장이 그 기능을 이 빌드에서 제외했으므로 **13장이 우선**이다.
지금 루프에 꽂으면 13장이 검증하려는 가설 두 개에 노이즈만 더한다.

정리 사항: 안 쓰는 화면 2개가 `UIManager.prefab`의 `screenPrefabs`에 등록돼 매 세션 프리팹 참조로 로드된다.
기획 단계가 그 기능에 도달하기 전까지는 등록만이라도 빼는 편이 안전하다.

## 미검증

- **2인 멀티플레이 실검증 (Host 1 + Client 1, 서로 다른 팀 2개).** `AGENTS.md` QA 게이트가 요구하는 필수
  항목인데 이번 회차에서 실행하지 못했다. 다음 회차의 최우선 항목이다. 확인할 것:
  - 팀 배정이 두 클라이언트에 각각 붙고 각자 자기 팀 값을 읽는가
  - 팀 A가 팀 B의 `PrepIsland`/`Station`/`Counter`/`Sink`/`IngredientShelf`를 조작할 수 없는가
  - `PlayerCarry.view` 유출 실측 (P-4 확정용):
    ```csharp
    foreach (var p in NetworkManager.Singleton.SpawnManager.PlayerObjects)
        Debug.Log($"{p.OwnerClientId} team={p.GetComponent<PlayerTeam>().Team} " +
                  $"hand={p.GetComponent<PlayerCarry>().View.Label}");
    ```
    상대 팀의 `hand`가 실제 값으로 나오면 확정
  - `ItemBox` 공유 공개 시계: A가 박스를 열어 슬롯 일부 공개 → 이탈 → B가 같은 박스를 열었을 때
    처음부터 다시 기다리지 않는가. 다음 밤에 전부 가려진 상태로 리셋되는가
  - Host 종료 시 Client가 안전하게 빠져나오는가
- **`TeamStock`의 실제 복제 범위.** Cafe 루트 NetworkObject 하위인지 확인 필요. 하위면 무해, 아니면 P-4와 동급.
- **`PrepIsland` 추가로 인한 NetworkBehaviourId 순서 변경.** Host/Client가 같은 프리팹을 쓰면 무해하나 미확인.
- **세 화면을 실제 전환 페이즈 흐름에서 여는 경로.** 검수는 전부 `eval`로 직접 `ReplaceScreen`+`Bind` 했다.
- **`SetWaiting`/`SetRemaining` 매 프레임 갱신 성능**, **비-1.0 UI 스케일에서의 TMP Dynamic 아틀라스 재굽기 비용.**
