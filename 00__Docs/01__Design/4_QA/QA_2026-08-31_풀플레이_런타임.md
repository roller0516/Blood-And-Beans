  - 탈출 경로 차단: `Assets/Scripts/Client/MatchFlow.cs:106-107`


  16:9보다 **좁은** 쪽(4:3 등)에서는 논리 높이가 커지므로 증상이 없다 — 넓은 쪽 전용 결함이다.
- **영향 범위:** 울트라와이드에서 판이 끝나면 로비로 돌아갈 수 없다. ESC는 `MatchFlow.OnCancel`이
  `PopupDepth > 0`이면 아무것도 하지 않아 대체 탈출 경로도 없다.

### M-2. 낮 HUD의 손님 종족이 영문 열거자 이름으로 나온다 — `DisplayNames`를 우회한다

  단일 출처가 이미 있다 — `Assets/Scripts/Rules/DisplayNames.cs`의 `RaceNames` / `Of(Race)`.
- **파일과 라인 (최초 보고 시점):** `Assets/Scripts/Client/UI/MatchHudPresenter.cs:154`

  ```csharp
  text.AppendLine($"{customer.Kind} · x{customer.Remaining} · 인내 {customer.PatienceRatio * 100f:0}%");
  ```

- **기대 결과:** `늑대인간 · x3 · 인내 58%`
- **실제 결과:** `Werewolf · x3 · 인내 58%`. 같은 판의 전환 정산 화면은 같은 종족을
  「늑대인간」으로 써서, 한 판 안에서 같은 대상의 이름이 화면마다 달랐다.
- **영향 범위:** 낮 HUD 전체. 팀 표기도 같은 문제였다 — `MatchHudPresenter.cs:271`의

  HUD는 `1. Team 0 · 0g`, 최종 결산은 `1팀`으로 나왔다.

> **원본 보고서의 틀린 전제 — 정정.** 원본은 `customer.Kind`를 `Race` 열거자라고 적었으나

> **CS0246으로 컴파일 실패**했다. 규칙 계층이 게임 계층에 의존하게 되어 `AGENTS.md`의 DIP를

### M-3. 낮에는 대시가 아예 동작하지 않는다 — 기획서 11장 조작표와 다르다

- **심각도:** 중간
- **기획서 근거:** 11장 조작 표. `Space` 행이 **낮 = "짧은 거리 대시"**, 밤 = "대시 — 상대에게
  부딪히면 견제"다. 낮에 없어져야 하는 것은 **견제 효과이지 대시 이동 자체가 아니다.**
- **파일과 라인:** `Assets/Scripts/Night/DashHarass.cs:170-172`

  ```csharp
  var phase = MatchDirector.Instance?.Phase;
  if (phase == null || phase.Current != Phase.Night) return;
  ```

  견제 가능 여부는 `HarassAllowedServer()`가 따로 판정하므로, 이 게이트는 **이동으로서의
  대시까지** 낮에서 통째로 막았다.
- **재현 절차:** 낮 페이즈에서 Space. 서버 RPC(`DashRpc`)가 조기 반환한다.
- **기대 결과:** 낮에도 짧은 대시로 이동한다 (5.4의 긴 동선을 전제로 한 조작이다).
- **실제 결과:** 아무 일도 일어나지 않는다. HUD의 대시 슬롯도 낮에는 꺼져 있었다 —
  `MatchHudPresenter.cs:89`가 `Phase.Night`일 때만 `FillDash`를 불렀다.
- **영향 범위:** 낮 협동 운영 전체의 이동 감각. 5.4가 "설비 배치로 동선을 길게 만들어 분업을
  유도한다"고 한 레이아웃에서 이동 보조 하나가 빠진 상태였다.

#### 수정 및 실측 (2026-08-31)

**수정 전 안전성 확인이 먼저다.** `DashHarass.cs:122`의 타격 판정이 `HarassAllowedServer()`를
거치고, 그 함수가 `phase.Current == Phase.Night`를 요구하는 것을 코드로 확인했다. 따라서 이동
게이트를 열어도 낮에 견제가 발생하지 않는다.

```csharp
// 이동으로서의 대시는 밤과 낮 모두 된다 (기획서 11장 조작 표: 낮 = "짧은 거리 대시").
// 낮에 없어지는 것은 견제 효과뿐이고, 그 판정은 HarassAllowedServer가 따로 본다
// (기획서 4장 Night 0, 6.4). 전환은 조작을 받지 않는 정산 구간이라 제외한다.
var phase = MatchDirector.Instance?.Phase;
if (phase == null || phase.Current == Phase.Transition) return;
```

HUD의 `FillDash` 호출도 밤 전용 블록 밖으로 꺼내 `Phase.Transition`이 아닐 때 부르도록 했다.

**수정 후 실측 (낮 페이즈 확정 상태에서 서버 RPC 직접 호출)**

```
phase = 2/Day  remaining=100.4
CooldownRemaining before      = 0
--- after DashRpc during DAY ---
DashStarted fired             = True      <- 수정 전에는 조기 반환으로 발화하지 않았다
CooldownRemaining after       = 6
SuppressesInputServer after   = True
```

HUD 쪽도 낮에서 `DashSlot activeInHierarchy = True`, 「대시 / 준비」 표시를 확인했다.

**측정 시 주의 — 헛돌기 쉬운 함정.** `GamePhase.EndPhaseNowServer()`는 **같은 프레임 안에서
`Current`에 즉시 반영되지 않는다.** 한 `eval` 안에서 `while (Current != Day) EndPhaseNowServer()`
같은 루프를 돌리면 낮을 지나쳐 다음 밤까지 밀린다. 호출을 `eval` 단위로 쪼개 한 번에 한 페이즈씩
확인하며 전진해야 한다.

**미검증으로 남는 것:** 낮에 견제가 실제로 차단되는지는 **코드 확인까지만**이다. 부딪히는
경로를 실행하려면 2인 세션이 필요해 런타임으로 재현하지 못했다.
