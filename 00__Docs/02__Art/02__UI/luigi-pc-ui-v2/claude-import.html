낮·밤 화면에서 「현재 시안 / 절제형」을 선택해 비교하실 수 있습니다. 낮·밤은 인게임 카메라 구도를 기준으로, 로비·제조 시안과 같은 입체 글자와 UI 재질로 맞췄습니다.

1. 시각 방향

루이지 시안: 기존 제조·로비·루팅의 디자인을 기준으로 패널·입체 글자·아이콘·그림자를 한 세트로 다시 그렸습니다. 카메라는 실제 낮·밤 구도를 참고하고 장면의 조명·재질은 콘셉트로 표현했습니다. 조합법·주문 비교는 같은 낮 이미지, 상자·밤 부품은 같은 밤 이미지 위에 투명 패널만 겹치므로 선택할 때 카메라가 바뀌지 않습니다. 현재 구현 캡처는 갤러리에 포함하지 않습니다.

루이지의 분위기는 귀여운 3D 유령·몬스터, 둥근 글자, 짙은 초록, 크림색, 따뜻한 조명으로 유지합니다. 곡선 간판의 실루엣, 실제로 깎아 만든 듯한 황동 테두리, 초록 가죽과 크림 슬롯으로 이전 시안의 입체감을 살립니다. 문양을 반복하거나 상시 네온을 넣지 않고, 상태를 알리는 색은 말풍선 채움·선택선·판정에 사용합니다.

이는 아트 작업 시작값입니다. 실제 게임 배경에서 대비를 확인해 조정합니다. 팀 색은 기존 TeamColors 원본을 따르고, UI 전체를 팀 색으로 칠하지 않고 이름표·팀 번호 등으로 제한합니다.

절제형: 승인된 현재 시안을 유지하면서 금속 테두리의 반사, 선택 주변 발광, 판정과 스킬의 장식 효과를 줄였습니다. 입체 서체·클립보드·초록 가죽·크림 슬롯과 게임 카메라 구도는 유지합니다. 낮·조합법·주문·제조·밤·루팅·밤 부품의 7개 화면에서 선택할 수 있습니다.

2. 시안 이미지를 실제 UI로 나누는 방법

시안 PNG 전체를 화면 배경처럼 붙이지 않습니다. 이번 갤러리의 입체 글자·UI는 콘셉트 이미지입니다. 구현할 때는 장면, 문자 없는 UI 패널, 아이콘, 글자, 선택 상태, 수치를 분리합니다. 제공된 메뉴·주문·루팅 비교판에도 문자가 포함되어 있으므로 그대로 동적 UI 에셋으로 사용하지 않습니다. 패널 외곽·클립은 Sprite로, 글자는 TMP Outline/Underlay로, 아이콘은 현재 모델을 동일한 조명에서 렌더링해 재현합니다. 수치와 문구는 기존 데이터에서 가져옵니다.

현재 UIThemeConfig.FontScale과 UIFontScale이 프리팹 기본 글자 크기에 배율을 곱합니다. 위 수치를 그대로 기본 크기에 넣고 배율까지 다시 곱하면 UI가 커집니다. 기본 크기 = 목표 최종 크기 ÷ 실제 테마 배율로 맞추거나, 기존 배율 정책을 명시적으로 정리한 뒤 적용합니다. 제목·본문·HUD를 일괄 축소하는 방식은 피합니다.

CanvasScaler는 기존 설정을 먼저 확인하고 Scale With Screen Size, 기준 1920×1080, Match 0.5를 초기 후보로 사용합니다. 각 HUD는 화면 모서리·상단 중앙 앵커에 연결하고 중앙 메뉴는 가용 폭에 맞춥니다. 화면 크기와 앵커 조합이 해상도 대응의 기본입니다. Unity 다중 해상도 공식 문서

21:9에서는 HUD만 가장자리로 이동하고 메뉴 폭은 제한합니다. 4:3에서 8명이 겹치면 캐릭터 배치를 4명씩 두 줄로 바꾸는 후보를 검토합니다. 전체 UI를 가로로 찌그러뜨리지 않습니다. 현재 시안은 16:9이며 이 두 해상도의 실제 Unity 적용 검증은 후속 작업입니다.

4. 서체

  • 제목·주요 행동: 갤러리에 포함된 Bagel Fat One. 통통한 글자와 짙은 외곽선·짧은 Underlay로 이전 시안의 입체감을 재현합니다.
  • 본문·설명·버튼: Jua. 설명문은 한 화면에서 필요한 길이만 표시합니다.
  • 타이머·매출·판정 영문: Coiny는 숫자·영문 전용 후보입니다. 한글은 Bagel/Jua 폴백으로 표시합니다.

세 폰트는 갤러리 fonts/의 TTF와 OFL 고지를 같이 전달합니다. 브라우저 글꼴을 지정했다고 Unity TMP에 자동 적용되지는 않습니다. 프로젝트 폰트 폴더에 넣고 TMP Font Asset을 생성·배선해야 합니다.

고정 UI 문구·숫자·키 힌트는 Static SDF 애셋, 사용자 이름 등 예측 불가능한 한글은 Dynamic fallback으로 분리하는 후보를 사용합니다. 한글 전체를 무작정 작은 Static atlas 하나에 넣지 말고, 실제 표시 문자 집합으로 용량과 누락을 확인합니다. Dynamic fallback은 1024 atlas를 시작값으로 잡고 Clear Dynamic Data On Build를 켭니다. Font Asset Scale=1, Outline/Underlay는 제목·숫자·본문별 공용 Material Preset으로 분리합니다. 숫자는 짙은 외곽선과 아래쪽 짧은 그림자를 적용하고 상시 Glow는 끕니다. 타이머 AutoSize는 끄고 고정 크기로 맞춥니다. 설치된 uGUI 2.5.0의 TMP 소스에서 atlasPopulationMode, fallbackFontAssetTable, isMultiAtlasTexturesEnabled와 clearDynamicDataOnBuild를 확인했습니다.

6. 다인 캐릭터 선택의 추가 작업

현재 CharacterStage는 이미 최대 8개의 실제 모델과 이름표 좌표를 지원합니다. 무대는 Canvas 자식이 아니라 별도 3D 객체와 전용 카메라로 둡니다. 화면은 SetRoster, SetLobby, SetClaims와 UICharacterNameplate를 재사용합니다.

다만 현재 배치는 SelfSeat=0 중심으로 좌우 번갈아 놓이고 카메라가 내 자리를 따라갑니다. 새 시안의 4팀×2명 그룹은 색만 바꿔서는 나오지 않습니다. 표현 전용 좌석 매핑을 만들고 팀·사용자 ID로 안정된 표시 순서를 정한 뒤, 전체 8인을 담는 카메라 구도와 팀 라벨을 적용해야 합니다. 서버 좌석 ID와 화면 표시 위치는 구분합니다. 입장·퇴장 때 내 캐릭터와 선택 상태가 다른 사람에게 옮겨가지 않는지 확인합니다.

4개 몬스터 외형과 5개 클래스는 서로 다른 기준입니다. 현재 CharacterVisualConfig는 CharacterId에 연결된 모델을 고릅니다. 외형을 클래스별로 교체하는 것과 플레이어가 클래스와 별개로 4종 스킨을 선택하는 기능은 다릅니다. 후자는 별도 외형 선택 데이터/복제 검토가 필요하며, 이번 시안만으로 구현됐다고 보지 않습니다.

7. 주문·제조 오브젝트

UICustomerOrder는 patience.Show(1 - PatienceRatio, color)로 이미 사용한 인내심을 말풍선 안에 아래부터 채웁니다. UIBubbleFill의 공용 머티리얼과 정점 데이터를 재사용합니다. 별도 인내심 게이지를 새로 만들지 않습니다. 말풍선 Sprite가 바뀌면 투명 여백과 채움 range도 다시 맞춥니다. 가격은 기존 합계 탭 하나를 사용합니다.

실제 음료·컵·재료는 ItemVisualConfig와 ItemSlotPresenter의 기존 메시/재질을 사용합니다. UI 아이콘도 같은 프리팹을 일정한 카메라와 조명으로 오프라인 렌더링해 만들면 장면 오브젝트와 같은 형태가 됩니다. 각 주문·아이콘에 상시 Camera/RenderTexture를 붙이는 방식은 초기안에서 피합니다. 상세 회전 미리보기가 실제 요구된 곳에만 제한적으로 사용합니다.

UIMakingCard.Render(CarryView)는 현재 상태와 아이콘을 표시합니다. glowAlpha는 절제형에서 낮추되 블러드 빈의 공개 정보와 준비/실패 구분은 작은 상태 면·라벨로 유지합니다. 현재 제조 시안은 들고 있는 식기에 연결하는 카드 한 장과 옆의 판정 게이지를 보여줍니다. UICompletionGauge의 Good/Perfect 폭과 침 위치는 기존 CompletionGauge 값을 그대로 받아야 합니다. 그림의 녹색 영역 비율로 판정 수치를 새로 정하지 않습니다.

8. 공통 에셋 제작 목록

먼저 공용 기본 면·버튼·선택선·말풍선·상태 라벨·키 힌트·클래스 카드·행을 확정합니다. 기본/선택/호버/눌림/비활성은 색·작은 위치/스케일 변화로 만들고 상태마다 큰 PNG를 별도로 복제하지 않습니다. 반복 조각은 기존 Parts 프리팹과 해당 컴포넌트를 사용합니다.

텍스처는 최종 표시 크기 기준으로 제작합니다. 큰 시안에서 억지로 잘라 작은 아이콘으로 쓰기보다 글자 없는 개별 원본을 뽑습니다. Mipmap·필터·압축은 실제 UI 크기에서 비교하며, 텍스트는 이미지에 굽지 않습니다.

9. 적용 순서와 확인

  1. 공통 부품·서체·팔레트 확정 → 기존 UIThemeConfig와 공용 머티리얼/Parts 적용.
  2. 낮 HUD·주문·제조 → 실제 플레이에서 가장 작은 글자와 겹침 먼저 확인.
  3. 밤 HUD·루팅 → 밤에만 가방 표시, 적재·묻음·쿨타임 모든 상태 연결.
  4. 8인 캐릭터 선택 → 1/2/4/8인, 준비/퇴장/중복 픽·카메라·이름표 연결.
  5. 메뉴·정산·공통 팝업 → 공통 부품 재사용, 화면 스택과 입력 소유 유지.
  6. 후속 적용 검증 → 1920×1080, 2560×1080, 1600×1200; 긴 한글 이름·누락 글리프·부족 재고·손실·탄 것·로딩 상태; 실제 빌드에서 Canvas rebuild, 배칭, 오버드로 확인.

성능 목표 숫자는 측정 전 확정하지 않습니다. 동적 텍스트/표식은 갱신 범위를 좁히고 변화가 없으면 재설정하지 않습니다. 장식 Image의 Raycast Target은 끄고 실제 입력 요소만 켭니다. 많은 개별 Material, 중첩 Mask와 상시 UI 파티클을 줄입니다.

10. 확인한 근거와 남은 작업

현재 Unity 6000.5.9f1, uGUI 2.5.0, URP 17.5.0, Input System 1.20.0, NGO 2.13.1입니다. UIThemeConfig, UITheme, UIFontScale, UIRoundImage, UIBubbleFill, UICustomerOrder, UIMakingCard, UICompletionGauge, UIMatchHudScreen, MatchHudPresenter, CharacterStage, UICharacterSelectScreen, CharacterVisualConfig, ItemVisualConfig와 설치 패키지 소스를 확인했습니다.

「현재 시안 / 절제형」은 실제 게임의 후방 카메라 구도와 모델 형태를 참고해 생성한 콘셉트입니다. UI 부품은 같은 재질의 투명 패널로 겹칩니다. 제조 판정 게이지와 루팅 슬롯 공개는 상태 표현 예시입니다. Unity 프리팹 적용·빌드·게임 QA·다중 해상도 검증은 후속 작업입니다.
